# 자매 프로젝트 dori 검증 교훈

dori(dori.io.kr — 캔버스 기반 결정 도우미 모음)가 **실제 배포·AdSense 심사·모바일 실사용**에서
검증한 것 중 이 프로젝트에 적용 가치가 있는 것만 추린다 (2026-08-02 이관).
원본 근거·세부 이력은 dori 저장소의 `docs/commercial-plan.md` 6단계와 `docs/worklog-2026-08-01.md`.

같은 구조적 조건 — **전면 캔버스 홈 + 무료 브라우저 배포 + 모바일 지원** — 이라 대부분 그대로 적용된다.

## 1. 캔버스 게임의 홈은 크롤러에게 빈 페이지다

- 전면 캔버스 index.html은 검색·심사 크롤러에게 **텍스트 0인 화면**으로 보인다.
  dori는 정확히 이 이유로 AdSense "게시자 콘텐츠가 없는 화면" 반려를 받았고,
  검색 노출에도 같은 축의 불이익이 있다.
- **검증된 해법**: 캔버스 아래에 항상 렌더되는 DOM 섹션(h1 + 소개 몇 문장 + 실제
  `<a>` 링크들)을 둔다. 캔버스가 터치를 소유하므로 모바일 첫 화면 체감은 그대로다.
  Google 광고 미리보기의 노드 분류기가 이 섹션을 게시자 콘텐츠로 인식하는 것까지 확인했다.
- 이 프로젝트 적용: 1단계(무료 브라우저 = 바이럴 시드) 검색 유입에 직결.
  index.html에 게임 소개·조작법 요약·데브로그/스팀 링크 섹션을 두는 것을 검토.

## 2. 크롤러가 읽는 텍스트에 이모지 금지

- Google 광고 미리보기 등 일부 렌더러는 이모지 글꼴이 없어 **'??'로 깨져** 저품질
  콘텐츠처럼 보인다. dori는 정적 페이지 전체에서 이모지를 제거했다.
- 규칙: 대외 HTML 텍스트(제목·본문·링크 라벨·메타)에는 이모지를 쓰지 않는다.
  캔버스(WebGL) 안 렌더링은 무관. 단 이 프로젝트의 HUD는 DOM 오버레이라(🍟 바삭함 등)
  기술적으로는 같은 대상이다 — 게임 UI이므로 지금은 유지하되, 광고 심사를 진행하게 되면
  심사 도구에서 '??'로 보일 수 있음을 기억할 것.

## 3. 대외 문구는 소스 상수와 대조 후 배포

- dori 정밀 검토에서 안내 문구 20여 곳이 실제 코드와 어긋나 있었다 —
  수치 상한, 버튼 이름, 규칙 서술("절대 바뀌지 않는다"인데 다시 섞기 버튼 존재 등).
  심사와 사용자 신뢰 양쪽에 치명적이고, 쓴 사람은 스스로 발견하지 못한다.
- 규칙: 수치·조작명·규칙을 담은 대외 문구는 **소스 상수·동작과 대조 검증**을 거쳐 배포.
  이 프로젝트의 verify 스크립트 문화에 편입 후보 — 문구·상수 대조를 verify 케이스로.

## 4. 모바일 웹·인앱 브라우저 함정 (전부 실기기 검증)

- **클립보드**: `navigator.clipboard`는 카카오톡·네이버 등 인앱 브라우저에서 부재/차단된다.
  readonly textarea + `execCommand('copy')` 폴백을 붙이고, 그래도 실패하면 정직하게
  안내한다 (dori `src/ui.js`의 `copyText` 참조). 공유는 Web Share의 `AbortError`(사용자
  취소)만 무시하고 나머지 실패는 클립보드 폴백으로.
- **iOS 입력**: 전역 `-webkit-touch-callout: none`을 걸었다면 input/textarea에는
  `default`로 복원해야 길게 눌러 붙여넣기가 된다. DOM 오버레이(버튼·입력창)에는
  `touch-action: manipulation`으로 더블탭 줌을 차단.
- **기기 판정**: iPadOS 13+ Safari UA는 'Macintosh' — `maxTouchPoints > 1` 병행 판정.
  iOS 16.4 미만의 홈 화면 앱 감지는 `display-mode` 쿼리에 `navigator.standalone` 병행.
- **인앱 브라우저**: 설치·공유·`window.open`이 전부 제한된다. UA로 감지해
  "다른 브라우저로 열기" 안내 분기를 두고, `window.open` 반환값 null이면 무반응 대신 안내.

## 5. 웹 광고(AdSense)를 검토하게 된다면

현 로드맵(itch → 스팀)에는 없지만, 무료 브라우저 단계에서 광고를 붙일 경우
dori의 실심사 기록이 선행 체크리스트다:

- 1차 반려 사유 2종("게시자 콘텐츠가 없는 화면에 광고", "가치가 별로 없는 콘텐츠")과
  대응 전체가 dori `docs/commercial-plan.md` 6단계·6-1에 기록되어 있다.
- 요지: 광고 로더는 **콘텐츠(텍스트) 페이지에만** 배치 / 기능별 안내 페이지 + FAQ로
  고유 텍스트 볼륨 확보 / 사행·주류·아동 연상 문구 보수 운용 / ads.txt 선등록 /
  심사 요청 전 크롤러 관점 확인(아래 §7).

## 6. 릴리스 자산 생성 스크립트는 저장소에 커밋

- dori의 og 이미지 생성 스크립트가 세션 임시 폴더에만 있어 릴리스마다 재작성했다.
- 규칙: 릴리스에 필요한 자산 생성 스크립트(og 이미지·아이콘·홍보 스크린샷)는
  `scripts/`에 커밋한다. 이 프로젝트의 스크립트화 문화(verify.mjs 등)를 새 자산에도 유지.

## 7. 배포 전 점검 도구·방법

- **크롤러 관점 확인**: `msedge --headless=new --dump-dom <url>` — JS 실행 후의 DOM
  텍스트를 그대로 볼 수 있어 스크린샷보다 정확하다. "크롤러가 무엇을 읽는가"의 1차 근거.
- **3축 정밀 검토 프레임** (dori에서 대외 공개 직전 사용, 유효성 검증됨):
  ① 사실 정합 — 대외 문구를 코드와 전수 대조
  ② 심사관/신규 사용자 시뮬레이션 — 정책 리스크·얇은 콘텐츠·문장 품질을 남의 눈으로
  ③ 기술 정합 — 메타·canonical·og·sitemap·내부 링크·구조화 데이터 전수
  세 축을 병렬로 돌리고 교차 검증한다.
