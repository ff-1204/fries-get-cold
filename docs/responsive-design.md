# PC·모바일 대응 설계

PC 브라우저와 모바일 브라우저를 모두 지원하기 위한 고려사항.
원칙: **같은 빌드 하나로 두 환경을 커버한다** (입력·UI·성능만 분기, 콘텐츠 분기 금지).

## 1. 입력 — 가장 큰 분기점

| | PC | 모바일 (v0.7.0 — 조이스틱·반분할 폐지) |
|---|---|---|
| 시점(카메라) | 마우스 + Pointer Lock API | 화면 어디든 드래그 (터치 이동량 → 카메라 회전) |
| 이동 | WASD / 방향키 | **"걷는다" 버튼 홀드** (하단 왼손) — 직진뿐이라 조향 불필요 |
| 상호작용(전단지 읽기 등) | E 키 / 클릭 | 대상 근접 시 화면 버튼 표시 → 탭 |
| 지적 (이상 짚기) | 크로스헤어 조준 + 클릭 | 사물을 직접 탭 (크로스헤어 숨김 — 탭 지점이 조준) |

- **Pointer Lock은 터치 기기에 없다.** 입력 모듈을 인터페이스로 추상화하고
  `pointerdown`의 `pointerType`(mouse/touch)으로 런타임 감지해 자동 전환.
  기기 감지(UA 스니핑)로 고정하지 말 것 — 터치스크린 노트북, 태블릿+키보드 존재.
- 이 게임은 조작이 단순(걷기+보기+탭)해서 모바일 이식성이 좋은 편.
  **복잡한 조작을 추가하고 싶어질 때마다 모바일 UI를 먼저 그려보고 결정한다.**
- 걷기 버튼은 홀드 = 전진 (v0.7.0): 손을 떼면 그 자리에서 관찰 —
  "걷기 ↔ 관찰"의 전환이 별도 조작 없이 몸에 붙는다. 3D 이중 드래그(이동+시점 동시)를
  요구하지 않는 것이 핵심 (한 손은 홀드만, 시선만 능동 조작)

## 2. 화면·뷰포트

- **가로/세로 모두 지원이 목표. 단, 권장은 가로(landscape).**
  세로 모드에서는 FOV를 키우고(수직 시야 확보) UI를 재배치. 구현 부담이 크면
  1차 출시는 "세로에서 회전 안내 오버레이"로 시작하고 세로 대응은 이후 과제로.
- 모바일 주소창 문제: `100vh` 대신 **`100dvh`** + `visualViewport` API 사용.
  캔버스 리사이즈는 `resize` + `orientationchange` 둘 다에서 처리.
- `devicePixelRatio`는 **최대 2로 캡** (3배 렌더링은 발열·프레임 저하만 유발).
- iOS Safari 제스처 충돌: 화면 가장자리 스와이프(뒤로가기)와 카메라 드래그가
  겹치지 않게 가장자리 안전 영역(safe area inset) 확보. `touch-action: none` 필수.
- 노치/펀치홀: `env(safe-area-inset-*)`로 HUD(구간 카운터, 조이스틱) 배치.

## 3. 성능 — 모바일이 기준선

- **성능 예산은 모바일 기준으로 잡는다** (development.md의 30fps@중급 모바일이 하한선).
  PC에서 잘 돌고 모바일에서 안 돌면 실패, 역은 없음.
- 품질 자동 분기: 시작 시 1~2초 마이크로 벤치마크(또는 `navigator.hardwareConcurrency`,
  WebGL 익스텐션 확인)로 티어 결정 →
  - **Low**: 그림자 끔, 안개 밀도로 원거리 컷, 픽셀 비율 1.0, 포스트프로세싱 끔
  - **High**: 주광원 그림자, 픽셀 비율 ≤2, 비네트/그레인 포스트
  - 설정 메뉴에서 수동 변경 가능하게.
- 발열·배터리: 모바일에서 프레임 캡 옵션(30/60fps) 제공. 정지 화면(스마트폰 UI
  열람 중)에는 렌더 루프 스로틀.
- 메모리: 모바일 Safari는 WebGL 컨텍스트 메모리에 민감 — 텍스처 KTX2 필수,
  구간 프리팹 재사용으로 씬 메모리 고정.

## 4. 모바일 브라우저 특유의 함정

**구현 현황 (v0.2.1)**: 아래 항목 중 뒤로가기 트랩(popstate → 일시정지 오버레이, 이탈 방지),
beforeunload 가드(걷는 중일 때만), overscroll-behavior(당겨서 새로고침 방지),
gesturestart·contextmenu 차단(핀치 줌·길게 눌러 메뉴), Wake Lock(복귀 시 재요청),
pageshow bfcache 복구(iOS 스와이프 복귀 시 오디오·시계 재개)가 구현되어 있다 — `src/main.ts` 하단.

- **오디오 자동재생 금지**: iOS/Android 모두 첫 사용자 제스처 전 소리 재생 불가.
  → 시작 화면에 "탭하여 시작" 게이트를 두고 그 탭에서 AudioContext resume.
  호러는 소리가 절반이므로 이 게이트에서 **"이어폰 권장 🎧" 안내**도 함께.
- **탭 백그라운드 전환**: `visibilitychange`에서 게임 일시정지 + 오디오 정지.
  복귀 시 연출·쿨다운 등 타이머류가 튀지 않게 델타타임 클램프.
- **전체화면**: Android는 Fullscreen API 사용 가능, iOS Safari는 불가 —
  iOS는 홈 화면 추가(PWA, `display: standalone`)를 안내하는 정도로 타협.
- **화면 꺼짐 방지**: 플레이 중 Wake Lock API (지원 브라우저 한정, 실패해도 무시).
- **컨텍스트 손실**: `webglcontextlost` 핸들링 — 복구 시도 + 안내 문구
  (모바일에서 드물지 않음).

## 5. UI 스케일링

- HUD는 px 고정이 아니라 **뷰포트 상대 단위 + 최소 크기 보장** (`clamp()`).
- 터치 타깃 최소 44×44pt (상호작용 버튼, 설정 메뉴).
- 스마트폰(커뮤니티 앱) UI: DOM 오버레이라 반응형이 쉬움 —
  모바일에서는 전체 화면, PC에서는 화면 중앙 4:9 패널로.
- 자막(모놀로그)은 모바일 최소 14px 상당 보장, 폰트 스케일 옵션 제공.
- **어두운 게임 + 야외 모바일 플레이 = 안 보임.** 밝기(감마) 슬라이더를
  시작 화면에서 바로 제공 ("이 문구가 겨우 보일 정도로 조절하세요" 패턴).

## 6. 호러 연출의 환경 차이

- 모바일은 화면이 작아 원거리 이상현상이 안 보인다 —
  이상현상 배치 시 **"모바일 화면에서 3초 안에 발견 가능한가"를 명확성 기준에 추가**
  ([anomalies.md](./anomalies.md) 원칙 1과 연동).
- OLED 폰은 순수 검정(#000)이 픽셀 오프되어 오히려 부자연스러움 —
  어둠은 아주 어두운 남색 계열로.
- 진동(Vibration API, Android 한정)은 심장박동 등 연출에 옵션으로 활용 가능 — 남용 금지.

## 7. 테스트 매트릭스

| 환경 | 최소 확인 항목 |
|---|---|
| Windows Chrome | 기준 환경 — 전 기능 |
| Windows Edge / Firefox | 입력·오디오·성능 스팟 체크 |
| macOS Safari | WebGL 렌더 차이, 오디오 게이트 |
| Android Chrome (중급 실기기) | 성능 하한선, 터치 조작, 전체화면, 진동 |
| iOS Safari (실기기) | 오디오 게이트, dvh/주소창, 제스처 충돌, 발열 |

- 릴리즈마다 최소한 Android·iOS 실기기 각 1회 ([workflow.md](./workflow.md) 릴리즈 절차와 연동).
- 에뮬레이터(DevTools 디바이스 모드)는 레이아웃 확인용일 뿐 —
  성능·오디오·제스처는 실기기만 신뢰한다.
