# 스테이지 — 밤 단위 관리

**이 게임의 스테이지는 「밤 N」이다.** 이 문서는 하나뿐이다:
**무엇이 모든 밤에 공통이고, 무엇이 밤마다 달라지는가**를 정하고, 그 경계에 맞춰
기획(결정된 것)과 구현(실빌드)을 대조한다.

- 기획 원본은 여기 옮겨 적지 않는다 — 밤별 시스템·서사는 [game.md](./game.md)
  '구조 — 다섯 밤' 표와 [story.md](./story.md) §5–6이 원본이다.
  (같은 내용을 두 곳에 적으면 다음 세션에 갈라진다 — pm-review 2026-08-03의 결론)
- 이 문서가 원본인 것: **공통/스테이지별 경계**, **밤별 구현 현황판**,
  **밤 분기가 코드에 흩어진 위치**, **스테이지 데이터 스키마**, **추가 절차**.

---

## 0. 왜 '밤'이 스테이지인가

진행·저장·서사·난이도·해금이 전부 밤 단위로 움직인다. 저장은 정수 하나(`save.night`)뿐이고,
밤이 넘어갈 때만 세계가 달라진다.

**구간(테마)은 스테이지가 아니다.** 원룸 골목·상가 골목·놀이터 옆길·정류장 앞·먹자골목 입구는
*장소*이고 **매 밤 그대로 재사용**된다 (귀갓길은 테마 5→1 역순). 접힘은 그 장소를 반복시킬 뿐이다.

좌표계로 쓰면 이렇다:

```
스테이지 = 밤 N
  └ 구간 = done/total (기본 5, 접힘마다 +1)
      └ 테마 = 5→1 역순 (장소. 밤과 무관하게 공통)
```

## 1. 공통 / 스테이지별 경계 ⭐

**새 요소를 넣을 때 먼저 이 표에서 어느 쪽인지 정한다.** 스테이지별 칸에 들어가는 것은
반드시 데이터로 표현할 수 있어야 한다 (§4).

### 공통 — 모든 밤에 동일하다

| 항목 | 원본 |
|---|---|
| 코어 규칙 2축 (흔적=직시 / 사람 형태=외면), 접힘, 깊이 사다리, soft fail | [spec.md](./spec.md) §2–3 |
| 판정 임계값 — 직시 4.5m, 응시 11m·시선축 12°·2.2초·경고 0.4초·회복 2.5배 | `config.ts` |
| 이상현상 등장 확률 — 기본 0.4 + **경과 1분당** 0.06, 상한 0.8 (밤이 아니라 시간이 올린다) | `config.ts` |
| 공간 — 공용 복도 프리팹 + 테마 5종 + 앞뒤 다리 밑 터널 | `src/world/` |
| 이동·조작·HUD·자막·저장 스키마 | `input.ts` `hud.ts` `save.ts` |
| 완주 등급 (접힘 0 / 1–2 / 3+ → 귀가 문구) | `balance.ts` |
| 차도 신호 주기 9초 (초록 3.5 / 점멸 2.5 / 빨강 3) | `world/layout.ts` |

### 스테이지별 — 밤마다 달라진다

| 항목 | 지금 어디에 있나 | 데이터인가 |
|---|---|---|
| 해금 이상현상 풀 | `data/anomalies.json` 각 항목의 `night` | ✅ 데이터 |
| 인트로 (가게를 나서며) | `data/stages.json` `intro` | ✅ 데이터 |
| 에필로그 (집 도착 — Peak-End의 End) | `data/stages.json` `epilogue` | ✅ 데이터 |
| 온보딩 보장 (퇴근길 튜토리얼·첫 구간 강제 정상·무이상 방지·조작 힌트) | `data/stages.json` `onboarding` | ✅ 데이터 |
| 도장 칸 수 / 칸 밖 도장 시점 | `STAGE_COUNT` = stages.json 길이 | ✅ 파생 |
| 세트피스 1개 | **미구현** | ❌ |
| 규칙형 괴담 (존재별 예외 규칙) | **미구현** | ❌ |
| 힌트 시스템 / 커뮤니티 앱 | **미구현** | ❌ |
| 엔딩 분기 (밤 5) | **미구현** | ❌ |

> **원칙 재확인**: "콘텐츠는 데이터, 로직은 시스템" (design-principles).
> **스테이지 추가에 코드 수정이 필요하면 설계 실패다.**
> 지금 구현된 것(✅)은 stages.json에 밤을 한 줄 더하면 끝난다 — 코드는 건드리지 않는다.
> 남은 ❌ 넷은 **그 시스템 자체가 없는 것**이라, 시스템이 생길 때 §4에 필드를 더한다
> (지금 빈 필드를 미리 넣어두지 않는다 — 아무도 읽지 않는 스키마는 거짓말이 된다).

## 2. 밤별 구현 현황판

기획 내용은 [game.md](./game.md) '구조 — 다섯 밤' 표가 원본. 여기는 **실빌드 대조**만 한다.
✅ 구현 · 🟡 부분 · ❌ 없음 (v0.11.23 기준)

| 밤 | 인트로 | 에필로그 | 이상현상 풀 | 세트피스 | 규칙형 괴담 | 힌트·앱 | 엔딩 |
|---|---|---|---|---|---|---|---|
| 1 | ✅ | ✅ | ✅ 5종 (+튜토리얼·강제 정상·무이상 방지) | ❌ | — | — | — |
| 2 | ✅ | ✅ | ✅ +4종 (누적 9종) | ❌ | ❌ | ❌ | — |
| 3 | ✅ | ✅ | ❌ **신규 0종** (밤 2 풀 그대로) | ❌ | ❌ | ❌ | — |
| 4 | ✅ | ✅ | ❌ 신규 0종 | ❌ | ❌ | ❌ | — |
| 5 | ✅ | ✅ | ❌ 신규 0종 | ❌ | ❌ | ❌ | ❌ |
| 6+ | 🟡 밤 5 문구 반복 | 🟡 반복 | 밤 2 풀 그대로 | — | — | — | — |

**읽는 법 — 지금 이 게임은 밤 2에서 포화된다.** 밤 3·4·5는 인트로·에필로그 문구를 빼면
**밤 2와 기계적으로 완전히 동일하다.** 난이도조차 오르지 않는다:

- 이상현상 확률은 `min(0.8, 0.4 + (경과분 × 0.06))`이고 **`경과`는 밤마다 0으로 리셋된다**
  (`main.ts:126`). 즉 확률 곡선은 **모든 밤이 같은 곡선**이지 밤 번호를 타지 않는다.
- 증식·깊이도 그 밤 안에서 접힘·빈 지적으로만 오른다 — 역시 밤 번호와 무관하다.

그래서 M3에서 밤 3~5에 필요한 것은 '난이도 조정'이 아니라 **콘텐츠**다
(신규 이상현상 · 세트피스 · 규칙형 괴담 · 엔딩). 밤별로 난이도를 다르게 하고 싶다면
그건 **새 결정**이고 §1 표를 먼저 고쳐야 한다.

실측 근거 (2026-08-03, v0.11.23): `anomalies.json` 총 9종 = `night:1` 5종 + `night:2` 4종,
`night:3` 이상 0종. `stages.json` 5개(밤 1~5), 밤 6+는 `stageOf()`가 마지막 것을 재사용.
저장을 밤 1·2·3·5·6·8로 시드해 인트로·모드·도장 칸을 전수 확인.

## 3. 밤 분기 — 코드에 남은 것

v0.11.22까지 `main.ts`에 밤 번호 하드코딩이 10곳 있었고, v0.11.23에서 데이터로 내렸다.
**지금 남은 밤 분기는 셋뿐이고, 셋 다 하드코딩이 아니다:**

| 위치 | 하는 일 | 왜 남아도 되나 |
|---|---|---|
| `a.night <= night` | 이상현상 풀 해금 | 값이 `anomalies.json`에 있다 (밤은 이상현상의 속성) |
| `night > STAGE_COUNT` | 도장 칸 밖 문구 | `STAGE_COUNT` = stages.json 길이에서 파생 |
| `save.night > 1` | 타이틀에 도장 카드를 띄울지 | **스테이지 속성이 아니라 "진행이 있는가"** |

해소된 7곳: 첫 구간 강제 정상 · 무이상 방지 · 퇴근길 튜토리얼 진입 · 온보딩 힌트 표시 ·
힌트 해제 → 전부 `stageOf(night).onboarding` / 인트로·에필로그 선택 → `stageOf(night)` /
도장 칸 계산 5곳 → `STAGE_COUNT`.

**밤을 추가하는 데 이제 코드가 필요 없다** — `stages.json`에 한 줄, 이상현상은
`anomalies.json`에 `night` 지정. 이 표에 줄이 늘어나면 그 자체가 신호다 (§5-5).

## 4. 스테이지 데이터 스키마 (`src/data/stages.json` — v0.11.23 구현)

```jsonc
{
  "night": 1,            // 밤 번호 (배열 순서와 같게 — 사람이 행을 찾는 표식)
  "onboarding": true,    // 퇴근길 튜토리얼 + 첫 구간 강제 정상 + 무이상 방지 + 조작 힌트
  "intro": "…",          // 가게를 나서며 (그 밤의 목적을 한 번)
  "epilogue": "…"        // 집에 도착해서 (그 밤의 마지막 컷 — Peak-End의 End)
}
```

타입·접근자는 `src/data.ts`: `StageDef` · `STAGES` · `STAGE_COUNT` · `stageOf(night)`.

**설계 결정 네 가지**

1. **이상현상 풀은 옮기지 않았다.** `anomalies.json`의 `night`이 원본이다 —
   어느 밤부터 나오는지는 *그 이상현상의* 속성이지 스테이지의 속성이 아니다.
2. **밤 6+ 클램프는 데이터가 아니라 시스템의 것이다.** `stageOf()`가 배열을 넘어가면
   마지막 스테이지를 재사용한다. 엔딩이 구현되면 이 클램프는 사라진다.
3. **`STAGE_COUNT`(= 배열 길이)가 도장 칸 수다.** 밤을 더하면 칸도 따라 는다.
   ⚠ 단 `TEXT.couponOverflow`의 "여섯 번째"는 5칸 전제 문구라 함께 고쳐야 한다.
4. **미구현 시스템의 빈 필드는 넣지 않았다** (`setpiece` / `rules` / `ending`).
   아무도 읽지 않는 필드는 "이미 연결돼 있다"는 거짓 신호를 준다 —
   세트피스 시스템이 생기는 커밋에서 필드도 함께 생긴다.

난이도 노브(확률·증식·깊이)는 지금 **공통**이다 (§1). 밤마다 다르게 하고 싶어지면
**§1 경계표를 먼저 고치고** 여기 필드를 더한다. 순서를 뒤집지 않는다.

## 5. 스테이지를 추가·수정하는 절차

1. **§1 표에서 어느 쪽인지 정한다.** 공통이면 이 문서가 아니라 spec.md·config로 간다.
2. **기획을 원본에 적는다** — 시스템 도입은 [game.md](./game.md) 밤 표,
   서사 비트·마지막 컷은 [story.md](./story.md) §5.
3. **콘텐츠를 데이터로 넣는다** — 밤 자체는 `data/stages.json`에 한 줄,
   이상현상은 `data/anomalies.json`에 `night` 지정 (절차는 [anomalies.md](./anomalies.md)).
   **여기서 코드를 열어야 한다면 멈추고 §4를 먼저 고친다.**
4. **§2 현황판을 갱신한다** — 이 문서는 실빌드와 대조하는 표다. 릴리즈마다 본다.
5. **밤 분기 코드를 늘렸다면 §3에 등재한다.** 목록이 길어지는 것 자체가 신호다.
