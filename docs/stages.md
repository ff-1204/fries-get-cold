# 스테이지 — 밤 단위 관리

**이 게임의 스테이지는 「밤 N」이다.** 이 문서는 하나뿐이다:
**무엇이 모든 밤에 공통이고, 무엇이 밤마다 달라지는가**를 정하고, 그 경계에 맞춰
기획(결정된 것)과 구현(실빌드)을 대조한다.

- 기획 원본은 여기 옮겨 적지 않는다 — 밤별 시스템·서사는 [game.md](./game.md)
  '구조 — 다섯 밤' 표와 [story.md](./story.md) §5–6이 원본이다.
  (같은 내용을 두 곳에 적으면 다음 세션에 갈라진다 — pm-review 2026-08-03의 결론)
- 이 문서가 원본인 것: **공통/스테이지별 경계**, **밤별 구현 현황판**,
  **밤 분기가 코드에 흩어진 위치**, **스테이지 데이터 스키마**, **추가 절차**.

---

## 0. 왜 '밤'이 스테이지인가

진행·저장·서사·난이도·해금이 전부 밤 단위로 움직인다. 저장은 정수 하나(`save.night`)뿐이고,
밤이 넘어갈 때만 세계가 달라진다.

**구간(테마)은 스테이지가 아니다.** 원룸 골목·상가 골목·놀이터 옆길·정류장 앞·먹자골목 입구는
*장소*이고 **매 밤 그대로 재사용**된다 (귀갓길은 테마 5→1 역순). 접힘은 그 장소를 반복시킬 뿐이다.

좌표계로 쓰면 이렇다:

```
스테이지 = 밤 N
  └ 구간 = done/total (기본 5, 접힘마다 +1)
      └ 테마 = 5→1 역순 (장소. 밤과 무관하게 공통)
```

---

## 1. 공통 / 스테이지별 경계 ⭐

**새 요소를 넣을 때 먼저 이 표에서 어느 쪽인지 정한다.** 스테이지별 칸에 들어가는 것은
반드시 데이터로 표현할 수 있어야 한다 (§4).

### 공통 — 모든 밤에 동일하다

| 항목 | 원본 |
|---|---|
| 코어 규칙 2축 (흔적=직시 / 사람 형태=외면), 접힘, 깊이 사다리, soft fail | [spec.md](./spec.md) §2–3 |
| 판정 임계값 — 직시 4.5m, 응시 11m·시선축 12°·2.2초·경고 0.4초·회복 2.5배 | `config.ts` |
| 이상현상 등장 확률 — 기본 0.4 + **경과 1분당** 0.06, 상한 0.8 (밤이 아니라 시간이 올린다) | `config.ts` |
| 공간 — 공용 복도 프리팹 + 테마 5종 + 앞뒤 다리 밑 터널 | `src/world/` |
| 이동·조작·HUD·자막·저장 스키마 | `input.ts` `hud.ts` `save.ts` |
| 완주 등급 (접힘 0 / 1–2 / 3+ → 귀가 문구) | `balance.ts` |
| 차도 신호 주기 9초 (초록 3.5 / 점멸 2.5 / 빨강 3) | `world/layout.ts` |

### 스테이지별 — 밤마다 달라진다

| 항목 | 지금 어디에 있나 | 데이터인가 |
|---|---|---|
| 해금 이상현상 풀 | `data/anomalies.json` 각 항목의 `night` | ✅ 데이터 |
| 인트로 (가게를 나서며) | `data.ts` `TEXT.intros[night-1]` | △ 코드 내 배열 |
| 에필로그 (집 도착 — Peak-End의 End) | `data.ts` `TEXT.epilogues[night-1]` | △ 코드 내 배열 |
| 세트피스 1개 | **미구현** | ❌ |
| 규칙형 괴담 (존재별 예외 규칙) | **미구현** | ❌ |
| 힌트 시스템 / 커뮤니티 앱 | **미구현** | ❌ |
| 엔딩 분기 (밤 5) | **미구현** | ❌ |
| 도장 카드 표시 (밤 6+는 칸 밖) | `main.ts` 하드코딩 | ❌ 코드 |
| **밤 1 전용** — 퇴근길 튜토리얼, 첫 구간 강제 정상, 무이상 방지, 온보딩 힌트 | `main.ts` 하드코딩 | ❌ 코드 |

> **원칙 재확인**: "콘텐츠는 데이터, 로직은 시스템" (design-principles).
> **스테이지 추가에 코드 수정이 필요하면 설계 실패다.** 위 표의 ❌·△가 M3 착수 전에
> 갚아야 할 부채이고, 그 목표 형태가 §4다.

## 2. 밤별 구현 현황판

기획 내용은 [game.md](./game.md) '구조 — 다섯 밤' 표가 원본. 여기는 **실빌드 대조**만 한다.
✅ 구현 · 🟡 부분 · ❌ 없음 (v0.11.22 기준)

| 밤 | 인트로 | 에필로그 | 이상현상 풀 | 세트피스 | 규칙형 괴담 | 힌트·앱 | 엔딩 |
|---|---|---|---|---|---|---|---|
| 1 | ✅ | ✅ | ✅ 5종 (+튜토리얼·강제 정상·무이상 방지) | ❌ | — | — | — |
| 2 | ✅ | ✅ | ✅ +4종 (누적 9종) | ❌ | ❌ | ❌ | — |
| 3 | ✅ | ✅ | ❌ **신규 0종** (밤 2 풀 그대로) | ❌ | ❌ | ❌ | — |
| 4 | ✅ | ✅ | ❌ 신규 0종 | ❌ | ❌ | ❌ | — |
| 5 | ✅ | ✅ | ❌ 신규 0종 | ❌ | ❌ | ❌ | ❌ |
| 6+ | 🟡 밤 5 문구 반복 | 🟡 반복 | 밤 2 풀 그대로 | — | — | — | — |

**읽는 법 — 지금 이 게임은 밤 2에서 포화된다.** 밤 3·4·5는 인트로·에필로그 문구를 빼면
**밤 2와 기계적으로 완전히 동일하다.** 난이도조차 오르지 않는다:

- 이상현상 확률은 `min(0.8, 0.4 + (경과분 × 0.06))`이고 **`경과`는 밤마다 0으로 리셋된다**
  (`main.ts:126`). 즉 확률 곡선은 **모든 밤이 같은 곡선**이지 밤 번호를 타지 않는다.
- 증식·깊이도 그 밤 안에서 접힘·빈 지적으로만 오른다 — 역시 밤 번호와 무관하다.

그래서 M3에서 밤 3~5에 필요한 것은 '난이도 조정'이 아니라 **콘텐츠**다
(신규 이상현상 · 세트피스 · 규칙형 괴담 · 엔딩). 밤별로 난이도를 다르게 하고 싶다면
그건 **새 결정**이고 §1 표를 먼저 고쳐야 한다.

실측 근거 (2026-08-03, v0.11.22): `anomalies.json` 총 9종 = `night:1` 5종 + `night:2` 4종,
`night:3` 이상 0종. `TEXT.intros`/`epilogues` 각 5개, 밤 6+는 `Math.min(night-1, 4)`로 클램프.

## 3. 밤 분기가 코드에 흩어진 위치

새 밤을 추가할 때 **지금은 반드시 코드를 봐야 한다.** 전수 목록 (v0.11.22 `main.ts`):

| 위치 | 하는 일 | 데이터로 내려야 하나 |
|---|---|---|
| `:147` `a.night <= night` | 이상현상 풀 해금 | 이미 데이터 ✅ |
| `:152` `night === 1 && done === 0` | 밤 1 첫 구간 강제 정상 | ○ 스테이지 필드로 |
| `:154` `night === 1 && …` | 밤 1 무이상 방지 (강제 등장) | ○ |
| `:259` `intros[min(night-1, 4)]` | 인트로 선택 + 밤 6+ 클램프 | ○ |
| `:260` `night === 1 && !onboard.move` | 온보딩 힌트 | ○ |
| `:268` `night === 1 && …` | 퇴근길 튜토리얼 진입 | ○ |
| `:311` `night > 5` | 도장 칸 밖 문구 | ○ |
| `:317` `epilogues[min(night-1, 4)]` | 에필로그 선택 | ○ |
| `:709` `night === 1` | 온보딩 힌트 해제 | ○ |
| `:828` `save.night > 1` | 도장 카드 표시 | ○ |

10곳 중 **9곳이 밤 1 또는 밤 5/6 경계의 하드코딩**이다. 밤 3·4를 채우는 작업은
여기를 건드리지 않고 끝나야 한다 — 그러지 못하면 §4를 먼저 한다.

## 4. 스테이지 데이터 스키마 (제안 — M3 착수 시)

⚠ **미착수.** 아래는 §1의 ❌·△를 데이터로 내리기 위한 목표 형태이며,
확정 전에는 구현하지 않는다 (이 문서가 스키마를 '결정'하지는 않는다).

`src/data/stages.json`:

```jsonc
[
  {
    "night": 1,
    "intro": "튀김을 먹고 나왔다. 배가 부르다.\n집까지 걸어가면 된다. 그것뿐이다.",
    "epilogue": "문을 잠갔다. 두 번 잠갔다.\n…새로 생긴 가게가, 왜 24시간을 하지.",
    "onboarding": true,     // 퇴근길 튜토리얼 + 첫 구간 강제 정상 + 무이상 방지 + 힌트
    "setpiece": null,       // 세트피스 id (M3)
    "rules": [],            // 규칙형 괴담 id (M3)
    "ending": null          // 엔딩 분기 (밤 5)
  }
]
```

- 이상현상 풀은 **옮기지 않는다** — `anomalies.json`의 `night` 필드가 이미 원본이다
  (한 이상현상이 어느 밤부터 나오는지는 그 이상현상의 속성이지 스테이지의 속성이 아니다).
- 밤 6+는 배열 밖 → 마지막 항목을 재사용하는 규칙을 **데이터가 아니라 시스템**이 갖는다
  (현재의 `Math.min` 클램프와 같은 의미).
- 난이도 노브(확률·증식·깊이)는 지금 공통이다 — 스테이지별로 열고 싶어지면
  **§1 표를 먼저 고치고** 여기 필드를 추가한다. 순서를 뒤집지 않는다.

## 5. 스테이지를 추가·수정하는 절차

1. **§1 표에서 어느 쪽인지 정한다.** 공통이면 이 문서가 아니라 spec.md·config로 간다.
2. **기획을 원본에 적는다** — 시스템 도입은 [game.md](./game.md) 밤 표,
   서사 비트·마지막 컷은 [story.md](./story.md) §5.
3. **콘텐츠를 데이터로 넣는다** — 이상현상은 `anomalies.json`(`night` 지정,
   절차는 [anomalies.md](./anomalies.md)), 나머지는 §4가 생긴 뒤 `stages.json`.
4. **§2 현황판을 갱신한다** — 이 문서는 실빌드와 대조하는 표다. 릴리즈마다 본다.
5. **밤 분기 코드를 늘렸다면 §3에 등재한다.** 목록이 길어지는 것 자체가 신호다.
