# 스테이지 관리 — 밤 = 스테이지

**공통이 무엇이고 밤마다 달라지는 것이 무엇인가.** 새 요소를 넣을 때 먼저 이 문서에서
어느 쪽인지 정한다. 기획 내용은 [game.md](./game.md), 실빌드 명세는 [spec.md](./spec.md).

---

## 0. 왜 '밤'이 스테이지인가

진행·저장·서사·난이도·해금이 전부 밤 단위로 움직인다. 저장은 정수 하나(`save.night`)뿐이고,
밤이 넘어갈 때만 세계가 달라진다.

**구간(테마)은 스테이지가 아니다.** 원룸 골목·상가 골목·놀이터 옆길·정류장 앞·먹자골목 입구는
*장소*이고 **매 밤 그대로 재사용**된다. 늘어남은 그 장소를 반복시킬 뿐이다.

```
스테이지 = 밤 N
  └ 구간 = done/total (기본 5, 늘어남마다 +1)
      └ 테마 = 5→1 역순 (장소. 밤과 무관하게 공통)
```

### 방향 — 두 여정은 반대 방향이다

거리는 하나다: **원룸 골목(집) ↔ 먹자골목 입구(FF-1204).** 두 여정은 그 거리를 반대로 걷는다.

| 여정 | 구간 | 테마 순서 | 출발 → 도착 |
|---|---|---|---|
| 퇴근길 (첫날, 튜토리얼) | 2 | 4 → 5 | 정류장 → **FF-1204** |
| 귀갓길 (모든 밤, 본게임) | 5 | 5 → 4 → 3 → 2 → 1 | **FF-1204** → 집 |

**양방향으로 걷는 테마는 4·5 둘뿐이다** (1·2·3은 밤에만). 그래서 방향 문제도 거기서만 생긴다.

- ✅ **테마 순서** — `passSegment`가 귀갓길 `theme−1` / 퇴근길 `theme+1`
- ✅ **테마 5의 가게** — 퇴근길엔 앞(도착), 귀갓길엔 뒤(방금 나옴).
  `setShopNear` / `setBackScene`
- ✅ **테마 4의 현수막** — FF-1204를 가리키는 물건이라 **가게가 있는 쪽 갱구**에 건다.
  `setBannerSide`
- ✅ **좌우** — `setThemeMirror`가 반대 방향일 때 테마 그룹의 `scale.x`를 뒤집는다.
  테마마다 **저작된 방향**이 있다: 테마 4는 퇴근길 기준(정류장 → 횡단보도 → 가게 쪽 출구),
  테마 5는 귀갓길 기준(이상현상이 밤에 맞춰 배치돼 있다). 반대일 때만 뒤집는다.
  글자가 있는 것(현수막)은 그룹 안에서 되돌려 준다
- ⚠ **아직 남은 것 — 앞뒤 순서.** 횡단보도는 두 여정 모두 **부스 다음**이다.
  거리를 반대로 걸으면 순서도 뒤집혀야 하지만, **z까지 뒤집으려면 판정을 같이 뒤집어야 한다**:
  차도 판정이 `ROAD_Z`·`STOP_LINE_Z` 상수이고 차(`refs.car`)는 테마가 아니라 **공용 그룹**에
  있어서, 테마만 z 미러링하면 그려진 횡단보도와 치임 판정이 어긋난다.
  좌우 미러만으로도 "반대편을 걷고 있다"는 단서는 선다 — 순서는 그보다 덜 읽힌다

## 1. 공통 / 스테이지별 경계 ⭐

**새 요소를 넣을 때 먼저 이 표에서 어느 쪽인지 정한다.**
스테이지별 칸에 들어가는 것은 반드시 데이터로 표현할 수 있어야 한다 (§3).

### 공통 — 모든 밤에 동일하다

| 항목 | 원본 |
|---|---|
| 코어 규칙 2축, 늘어남, 깊이 사다리, soft fail | [spec.md](./spec.md) §2–3 |
| 판정 임계값 — 직시 4.5m, 응시 11m·12°·2.2초·경고 0.4초·회복 2.5배 | `config.ts` |
| 이상현상 등장 확률 — 기본 0.4 + **경과 1분당** 0.06, 상한 0.8 (밤이 아니라 시간이 올린다) | `config.ts` |
| 공간 — 공용 복도 프리팹 + 테마 5종 + 앞뒤 다리 밑 터널 + 목적지 둘 | `src/world/` |
| 이동·조작·HUD·자막·저장 스키마 | `input.ts` `hud.ts` `save.ts` |
| 완주 등급 (늘어남 0 / 1–2 / 3+ → 귀가 문구) | `balance.ts` |
| 차도 신호 주기 9초 (초록 3.5 / 점멸 2.5 / 빨강 3) | `world/layout.ts` |

### 스테이지별 — 밤마다 달라진다

| 항목 | 지금 어디에 있나 | 데이터인가 |
|---|---|---|
| 해금 이상현상 풀 | `data/anomalies.json` 각 항목의 `night` (+ `untilNight`) | ✅ 데이터 |
| 인트로 (가게를 나서며) | `data/stages.json` `intro` | ✅ 데이터 |
| 에필로그 (집 도착 — Peak-End의 End) | `data/stages.json` `epilogue` | ✅ 데이터 |
| 걸음 모놀로그 3줄 | `data/stages.json` `beats` | ✅ 데이터 |
| **밤별 압력** (확률 보너스·증식 하한) | `data/stages.json` `pressure` | ✅ 데이터 |
| 온보딩 보장 (퇴근길 튜토리얼·첫 구간 강제 정상·무이상 방지·조작 힌트) | `data/stages.json` `onboarding` | ✅ 데이터 |
| **규칙 배신** (같은 사물, 반대 규칙) | `anomalies.json` — `untilNight`로 끊고 `rule`만 바꿔 재등록 | ✅ 데이터 |
| 도장 칸 수 / 칸 밖 도장 시점 | `STAGE_COUNT` = stages.json 길이 | ✅ 파생 |
| 세트피스 1개 | **미구현** | ❌ |
| 규칙형 괴담 (존재별 예외 규칙 — "멈추면 안 되는 밤") | **미구현** | ❌ |
| 힌트 시스템 / 커뮤니티 앱 | **미구현** | ❌ |
| 엔딩 분기 (밤 5) | **미구현** | ❌ |

> **원칙**: "콘텐츠는 데이터, 로직은 시스템."
> **스테이지 추가에 코드 수정이 필요하면 설계 실패다.**
> ✅ 항목은 stages.json에 밤을 한 줄 더하면 끝난다. 남은 ❌ 넷은 **그 시스템 자체가 없는 것**이라,
> 시스템이 생길 때 §3에 필드를 더한다 — 지금 빈 필드를 미리 넣지 않는다.
> 아무도 읽지 않는 스키마는 거짓말이 된다.

## 2. 밤별 구현 현황판

기획 원본은 [game.md](./game.md) 밤 표. 여기는 **실빌드 대조**만 한다.
✅ 구현 · 🟡 부분 · ❌ 없음

| 밤 | 인트로 | 에필로그 | 모놀로그 | 이상현상 풀 | 압력 | 세트피스 | 규칙형 괴담 | 힌트·앱 | 엔딩 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | ✅ | ✅ | ✅ 3줄 | ✅ 5종 (+튜토리얼·강제 정상·무이상 방지) | — 기본 | ❌ | — | — | — |
| 2 | ✅ | ✅ | ✅ 3줄 | ✅ +4종 (누적 9종) | — 기본 | ❌ | ❌ | ❌ | — |
| 3 | ✅ | ✅ | ✅ 3줄 | ✅ **+4종** (누적 13종) | ✅ 확률 +0.05 | ❌ | ❌ | ❌ | — |
| 4 | ✅ | ✅ | ✅ 3줄 | ✅ +3종 (누적 16종) | ✅ +0.10 · 증식하한 1 | ❌ | ❌ | ❌ | — |
| 5 | ✅ | ✅ | ✅ 3줄 | ✅ +1종 (누적 17종) + **규칙 배신 1** | ✅ +0.15 · 증식하한 1 | ❌ | ❌ | ❌ | ❌ |
| 6+ | 🟡 밤 5 문구 반복 | 🟡 반복 | 🟡 반복 | 밤 5 풀 그대로 | 밤 5 값 그대로 | — | — | — | — |

**읽는 법 — 이제 다섯 밤 전부에서 새 것이 나온다.** 밤 5의 몫은 이상현상 수가 아니라
**규칙 배신**이다 (v0.11.46 — 그네의 형체가 그 밤에만 `avert` → `gaze`로 뒤집힌다).
남은 구멍은 엔딩이다.

**⚠ 난이도는 이제 밤 번호를 탄다** (v0.11.44 — 이전 설계의 의도적 번복).

- 예전 의도는 "확률 곡선은 모든 밤이 같다"였다. 그런데 인트로·에필로그를 빼면
  **밤 5가 밤 2와 똑같이 걸렸다.** 다섯 밤짜리 공포 게임에서 마지막 밤이 두 번째 밤과
  같은 압력이면 그건 다섯 밤이 아니라 **한 밤을 다섯 번** 하는 것이다
- 확률 = `min(0.8, 0.4 + 경과분 × 0.06 + 밤별 chanceBonus)`. `경과`는 여전히 밤마다 0으로
  리셋되므로 **곡선의 모양은 같고 시작 높이만 다르다**
- 동시 개수 = `1 + (증식 + 밤별 swarmFloor)` — 밤 4~5는 증식 없이도 둘부터 시작한다
- 노브는 `stages.json` `pressure`뿐이다. 코드에 밤 숫자를 적지 않는다

밤이 깊어지는 감각은 **압력과 해금 콘텐츠가 함께** 만든다.
남은 것은 세트피스 · 규칙형 괴담 · 힌트 시스템 · 엔딩 — 넷 다 **시스템이 아직 없다**.

**밤 6+의 동작** — `stageOf()`가 배열을 넘어가면 마지막 스테이지를 재사용한다.
밤 6부터 인트로가 밤 5의 것으로 고정되고, **밤 7부터 칸 밖 도장**이 찍힌다.
칸 밖 도장은 밤 8·9에서도 **한 개로 고정**이고 문구도 "여섯 번째"다 —
무한 모드의 의도된 단순화이지 카운트가 아니다. 엔딩이 구현되면 사라진다.

## 3. 스테이지 데이터 (`src/data/stages.json`)

```jsonc
{
  "night": 1,            // 밤 번호 (배열 순서와 같게 — 사람이 행을 찾는 표식)
  "onboarding": true,    // 퇴근길 튜토리얼 + 첫 구간 강제 정상 + 무이상 방지 + 조작 힌트
  "intro": "…",          // 가게를 나서며 (그 밤의 목적을 한 번)
  "epilogue": "…",       // 집에 도착해서 (그 밤의 마지막 컷 — Peak-End의 End)
  "pressure": {          // 없으면 기본값(0, 0) — 밤 1~2는 아예 적지 않는다
    "chanceBonus": 0.05, //   이상현상 확률에 더한다 (상한 0.8은 그대로)
    "swarmFloor": 1      //   증식의 하한 — 늘어남 없이도 동시 이상 1+floor
  },
  "beats": [             // 걸음 모놀로그 3줄 (그 밤의 3막을 따라간다)
    { "at": 0, "z": -13, "text": "…" }   // at = 몇 번째 구간, z = 그 구간 안의 위치
  ]
}
```

타입·접근자는 `src/data.ts`: `StageDef` · `STAGES` · `STAGE_COUNT` · `stageOf(night)` ·
`pressureOf(night)`.

**이 스키마의 판단 다섯 가지**

1. **이상현상 풀은 여기 없다.** `anomalies.json`의 `night`(·`untilNight`)이 원본이다 —
   어느 밤부터/까지 나오는지는 *그 이상현상의* 속성이지 스테이지의 속성이 아니다.
   **밤 5의 규칙 배신도 그래서 저쪽 파일에 있다**
2. **밤 6+ 클램프는 데이터가 아니라 시스템의 것이다.** 엔딩이 구현되면 사라진다
3. **`STAGE_COUNT`(= 배열 길이)가 도장 칸 수다.** 밤을 더하면 칸도 따라 는다.
   ⚠ 단 `TEXT.couponOverflow`의 "여섯 번째"는 5칸 전제 문구라 함께 고쳐야 한다
4. **미구현 시스템의 빈 필드는 넣지 않는다** (`setpiece` / `rules` / `ending`).
   세트피스 시스템이 생기는 커밋에서 필드도 함께 생긴다
5. **`beats`의 `at: -1`은 "마지막 구간"이다.** 절대 번호를 쓰면 늘어남으로 구간이 늘었을 때
   "거의 다 왔다"가 엉뚱한 데서 뜬다. 같은 이유로 **장소를 특정하는 문장을 쓰지 않는다** —
   같은 `at`이 다른 테마에서 뜰 수 있다

난이도 노브 중 **확률 보너스·증식 하한은 스테이지별**(`pressure`)이고,
곡선의 모양·깊이 사다리·판정 임계값은 **공통**이다 (§1).
새 노브를 밤마다 다르게 하고 싶어지면 **§1 경계표를 먼저 고치고** 여기 필드를 더한다.
순서를 뒤집지 않는다.

### 코드에 남은 밤 분기 — 넷뿐이고, 넷 다 하드코딩이 아니다

| 위치 | 하는 일 | 왜 남아도 되나 |
|---|---|---|
| `a.night <= night <= a.untilNight` | 이상현상 풀 해금·퇴역 | 값이 `anomalies.json`에 있다 (밤은 이상현상의 속성) |
| `pressureOf(night)` | 밤별 확률 보너스·증식 하한 | 값이 `stages.json` `pressure`에 있다 |
| `night > STAGE_COUNT` | 도장 칸 밖 문구 | `STAGE_COUNT` = stages.json 길이에서 파생 |
| `save.night > 1` | 타이틀에 도장 카드를 띄울지 | **스테이지 속성이 아니라 "진행이 있는가"** |

**밤을 추가하는 데 코드가 필요 없다.** 이 표에 줄이 늘어나면 그 자체가 신호다.

## 4. 스테이지를 추가·수정하는 절차

1. **§1 표에서 어느 쪽인지 정한다.** 공통이면 이 문서가 아니라 spec.md·config로 간다
2. **기획을 원본에 적는다** — 시스템 도입은 [game.md](./game.md) 밤 표,
   서사 비트·마지막 컷은 [story.md](./story.md)
3. **콘텐츠를 데이터로 넣는다** — 밤 자체는 `data/stages.json`에 한 줄,
   이상현상은 `data/anomalies.json`에 `night` 지정 ([anomalies.md](./anomalies.md)).
   **여기서 코드를 열어야 한다면 멈추고 §3을 먼저 고친다**
4. **§2 현황판을 갱신한다** — 이 문서는 실빌드와 대조하는 표다. 릴리즈마다 본다
5. **밤 분기 코드를 늘렸다면 §3 표에 등재한다.** 목록이 길어지는 것 자체가 신호다

## 5. 아직 결정되지 않은 것 (창작 결정 — 문서 정리로 확정하지 않는다)

- **엔딩 B의 명분** — 도장이 '무료 보상'이 아니라 '방문 기록'이므로 재설계가 필요하다
- **세트피스 5종의 구체 연출** — 밤 4 '골목의 호의', 밤 5 '가장 긴 귀갓길'만 방향이 있다
- **규칙형 괴담의 규칙 목록** — 방향("멈추면 안 되는 밤", "인사하면 안 되는 것")만 있고
  **동사 검증이 남아 있다**: 픽션이 아니라 새 손끝 감각인가?
