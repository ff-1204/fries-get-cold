# 이상현상 설계 — 밤의 골목에만 있는 것

핏자국, 백골, 창문의 얼굴, 그네에 앉은 형체. **밤의 골목에 있어서는 안 되는 것들.**

⭐ **이 문서가 이제 라이브와 같다** (v0.11.56 — M3 전환 완료).
짚기도 응시도 사라졌다. 아래에 적힌 "이상현상은 판정 대상이 아니다"가 문자 그대로 사실이다.

---

## ⭐ 이상현상은 판정 대상이 아니다

**아무것도 하지 않는다.** 쫓아오지 않고, 붙잡지 않고, 짚을 수 없고, 사라지지 않는다.
쳐다봐도 벌이 없고 눈을 돌려도 상이 없다. **처리할 수 없다.**

그것들이 하는 일은 하나다 — **플레이어를 멈춰 세우는 것.**
그리고 멈춰 있는 동안 골목이 자란다.

| | 이전 설계 | 목표 | 라이브 (v0.11.56) |
|---|---|---|---|
| 흔적 | 4.5m까지 다가가 **클릭하면 사라진다** | 그냥 있다. 지날 때까지 계속 있다 | ✅ 됐다 |
| 사람 형체 | 2.2초 이상 보면 **붙잡힌다** | 그냥 있다. 봐도 아무 일 없다 | ✅ **됐다** |
| 대가 | 판정 실패 → 늘어남 | **멈춘 시간** → 늘어남 | ✅ 됐다 (4초마다 한 구간) |

⭐ **그래서 배치의 목표가 바뀌었다.** 예전에는 "짚을 수 있게 보이는가"였고,
지금은 **"걸음을 멎게 하는가"**다. 멈춰 세우지 못하는 이상현상은 아무 일도 하지 않는다 —
가시성(§가시성)이 곧 효과다.

이 교체가 만드는 차이:

- **공포를 지우는 버튼이 없어졌다.** 이전에는 무서운 것을 클릭하면 없어졌다 —
  공포 게임이 플레이어에게 공포 제거 버튼을 쥐여주고 있었다
- **배울 것이 없어졌다.** 규칙을 모르는 사람에게도 첫 밤부터 똑같이 작동한다.
  긴장의 출처가 지식이 아니라 **반사**이기 때문이다
- **억울한 실패가 사라졌다.** 처벌 판정이 없으니 공정성 계산도, 경고 유예도,
  되돌릴 여지도 필요 없다. 남은 것은 카운터 하나뿐이고 그건 거짓말하지 않는다

⭐ **그래서 이 문서에는 규칙표가 없다.** 통과 조건도, 금기 목록도, 위반 판정도 없다.
이상현상에 관해 결정할 것은 딱 하나 — **무엇을, 어디에 세울 것인가.**

## 무엇이 좋은 이상현상인가

판정이 없어진 지금, 좋고 나쁨의 기준은 하나로 줄었다 —
**보는 순간 걸음이 멈추는가.** 아래는 그것을 만드는 방법들이다.

### 잘 듣는 것

- **늘 있던 것 위에 얹는다** — H-012(담 위), H-013(오토바이), H-016(벤치).
  새 물건이 나타나는 것보다, 익숙한 자리에 있어서는 안 되는 것이 있는 편이 더 어긋난다
- **정상의 반복을 무기로 쓴다** — H-011(닫힌 셔터 다섯 중 하나만 빛이 샌다),
  H-015·H-017. 학습된 정상이 두꺼울수록 위반 하나가 도드라진다
- **시선을 되받는다** — H-003(얼굴), H-006(눈). 자체 발광이라 어둠에 둘 수 있어
  배치도 자유롭다. **되받는 시선은 사람을 확실히 멈춰 세운다**
- **부재** — 늘 있던 프롭 하나를 **지운다.** 신규 지오메트리 0이고,
  정상이 두꺼운 테마 2·5에서 특히 강하다. 아직 안 쓴 수법이다
- **다수화** — 하나였는데 셋이다. 동시 등장 수를 올리면 무료로 나온다

### 정물이다 — 움직이지 않는다

**이미 그렇게 있다.** 등장 트윈도, 추격도, 혼자 흔들리는 그네도 없다.
가장 무서운 것은 달려드는 것이 아니라 **아까부터 거기 있었던 것**이다.

정물성은 새 설계에서 더 중요해졌다. 판정이 없으니 이상현상이 주는 압력은
**그 자리에 계속 있다는 사실** 하나뿐이고, 움직이는 순간 그게 이벤트가 되어 버린다.

### 애매한 것을 이제 만들 수 있다

우비인지 사람인지, 마네킹인지 형체인지 **끝까지 알 수 없는 것.**

이전 설계에서는 이것을 만들 수 없었다 — 조준만 해 보면 판정 반응으로 정체가 갈렸고,
게다가 헷갈린 대가가 붙잡힘이라 "애매하게 만들고 헷갈린 값을 물리는" 구조가 됐다.

⭐ **이제 만들 수 있다** (v0.11.56 — 판정이 하나도 남지 않았다).
조준으로 정체를 떠보는 길이 없고(v0.11.50), 사람인 줄 모르고 쳐다봐도 걸리지 않는다.
**애매한 것은 끝까지 애매하고, 남는 대가는 한 번 더 쳐다본 시간뿐이다** — 그 시간은
머무름 → 자람이 실제로 받는다 (v0.11.51). **다음에 만들 이상현상은 여기서 시작한다.**

⚠ 다만 단서는 정적인 형태여야 한다(움직임으로 정체를 드러내지 않는다). 쓸 수 있는 것:
**다리가 없다 · 받침대가 있다 · 관절 이음매 · 개수가 하나 더 많다 · 있을 수 없는 자리.**
그림자·흔들림·반사상은 렌더러에 없거나 정물성과 어긋난다.

## ⭐ 가시성 — 재 봤더니 절반이 화면에 없었다 (v0.11.49)

**가림 검사는 '밝기'를 재지 않는다**고 이 문서가 오래 경고해 왔는데, 실제로 재 본 적이 없었다.
`npm run verify:visible`이 그것을 잰다 — 구간을 걸으며 스크린샷을 뜨고,
이상현상이 차지한 사각의 휘도를 **그 둘레 배경**과 비교한다.

첫 측정 결과가 설계 실패를 그대로 드러냈다:

| | 접근 내내 최대대비 | 가림 검사 |
|---|---|---|
| 핏자국 · 끌린 자국 | **0.2 ~ 1.5** | 100% "뚫림" ✅ |
| 그네의 형체 · 오토바이의 형체 | **0.6 ~ 2.0** | 통과 ✅ |
| 백골 · 신발 · 어둠의 눈 · 간판 | 17 · 49 · 81 · 39 | 통과 ✅ |

**직시 대상이 안 보이면 곧바로 늘어남이었다.** 보이지 않는 것에 벌을 주고 있었다.

> v0.11.50에 그 벌은 사라졌다. **그런데 가시성은 더 중요해졌다** — 판정이 없으면
> 이상현상이 하는 일은 보이는 것 하나뿐이다. 안 보이면 그냥 없는 것이다.

### 왜 안 보였나 — 두 가지 실패

1. **어두운 것을 어두운 데 뒀다.** 형체 색(`0x0b0e16`)과 벽(`0x232838`)은 원래 휘도 차가 26인데,
   그 자리에 빛이 없으면 **둘 다 0으로 붕괴**한다. 형체 6종 중 4종이 이랬다.
   유일하게 성립한 정류장의 형체(대비 24)는 **부스가 제 형광등을 가진** 덕이었다
2. **바닥 자국은 거리에 약하다.** 눈높이 1.65m에서 15m 밖 바닥 데칼은 선으로 뭉개진다.
   게다가 마른 검붉은색은 아스팔트와 원래 휘도 차가 3뿐이다

### 통하는 수법 셋 (실측으로 확인)

- ⭐ **창백한 부분을 하나만 붙인다** — 얼굴은 안 보여도 **손은 보인다**.
  펜스의 손(H-020) 55 · 오토바이의 손(H-013) **2.0 → 49.3** · 셔터 하단 레일(H-015) 3.9 → 6.9.
  검은 실루엣이라는 정체를 지키면서 대비만 얻는 유일한 길이다
- **뒤에서 비춘다** — 놀이터 보안등을 세워 그네의 형체 0.6 → 7.1.
  ⚠ 그림자 렌더링이 없으므로(castShadow 0) 빛은 벽을 통과한다.
  **광원을 형체보다 뒤(−z)에** 둬야 형체의 카메라 쪽 면이 어둡게 남는다
- **가장 밝은 자리를 배경으로 쓴다** — 밝은 바닥 위의 **어두운 형상**(H-019).
  검은 것을 어둠에 세우는 것과 정확히 반대다
- **세로 요소를 준다** — 바닥 자국은 벽으로 이어 붙인다. 벽 자국은 거리와 무관하게 서 있다

### 여기에 넷을 더한다 (v0.11.57 — 미달 11건을 2건으로 줄이며 배운 것)

⭐ **① 세로 자국은 빛이 있는 면에 붙인다.** 핏자국·끌린 자국은 이미 벽 자국을 갖고
있었는데도 5.7이었다 — **가로등 반대쪽 벽**에 붙어 있었다. 자국 휘도 2.7, 그 둘레 벽 6.8:
둘 다 검었다. 광원 쪽 벽으로 옮기니 배경이 13.3이 되면서 11.7·22.6이 됐다.
*수법을 맞게 골라도 면을 틀리면 0점이다.*

⭐ **② 목표선은 배치로도 못 넘길 수 있다.** 백골은 밝기를 세 번 손봤는데도 6.5m에서
멈췄다. 원인은 밝기가 아니라 **구간 입구에서 6.8m 지점에 있었다** — 8m 떨어져 볼 방법이
없었다. 구간 중반으로 물리자 11.4m가 됐다. *미달이 안 풀리면 먼저 "그 거리에서 볼 수
있는 자리인가"를 확인한다.*

⚠ **③ "쪼개라"가 아니라 "사각이 대상으로 꽉 차게 하라"였다.** v0.11.49의 교훈(부품마다
따로 낸다)을 셔터의 손자국에 적용했다가 **14.5 → 2.6 (FAIL)**을 만들고 되돌렸다.
바닥의 흩어진 자국은 합집합 사각에 아스팔트가 섞여서 분할이 답이었지만,
**벽과 나란한 데칼은 늘 비스듬히** 보여 쪼갤수록 사각이 몇 픽셀로 줄고 그 안의 투명한
여백에 뒤의 셔터가 들어온다. 같은 규칙이 반대로 작동하는 경우가 있다.

⚠ **④ 색이 다른 것과 밝기가 다른 것은 다르다.** 벽의 핏자국(`0x4a0f0f`)은 벽(`0x232838`)과
**휘도가 거의 같았다** — 붉어서 눈에는 달라 보여도 지표로는 5.7이었다.
색상 대비는 어둠 속에서 가장 먼저 죽는다.

### 두 개의 선

| | 기준 | 뜻 |
|---|---|---|
| **FAIL** | 최대대비 < 4.5 | 화면에 없는 것과 같다. **배포를 막는다** |
| **WARN** | 대비 8이 8m 밖에서 안 나옴 | 걸어가다 알아보기 어렵다. 남은 작업 목록 |

8m 근거 (v0.11.50에 이유가 바뀌었다): 예전에는 "직시가 4.5m에서 성립하니 그전에 보여야
공정하다"였다. 지금은 **멈춰 세우려면 걸어오는 동안 보여야 한다**가 이유다 —
코앞에서야 보이는 것은 지나친 뒤에 알아차리게 되고, 그러면 풍경도 못 된다
(걷기 3.2m/s → 8m ≈ 2.5초).

**지금: 실패 0건 · 목표 미달 2건** (v0.11.57). 미달분은 위 표에 남긴다.

## 배치 — "존재"가 아니라 "보이는 것"이 완료 기준이다

판정이 없어진 뒤 배치는 **더** 중요해졌다.
이전에는 안 보이면 놓쳐서 늘어났지만, 지금은 안 보이면 **아무 일도 일어나지 않는다.**
보이지 않는 이상현상은 없는 것과 같다.

1. **광원 안쪽** — 구간 포인트라이트(가로등, `z = -L*0.45`) 사거리 안에.
   예외: 자체 발광형(눈·얼굴)은 스스로 빛나므로 어둠에 둘 수 있다
2. **관찰 시간 확보** — 구간 출구에서 최소 10m 앞에.
   ⭐ **다가갈 거리를 계산에 넣을 필요가 없어졌다** — 이제 다가가지 않기 때문이다.
   대신 **걸어가면서 보이는 시간**이 전부다
3. **실루엣 대비** — 어두운 형체는 밝은 배경(가로등 풀·유리) 곁에,
   밝은 것(백골)은 어두운 배경에

**②는 눈이 아니라 레이캐스트로 검증한다** — `?a=<effect>`로 고정하고
`window.__fries.occlusion()`을 구간의 여러 지점에서 호출한다.

⚠ **가림 검사는 '밝기'를 재지 않는다.** 셋 중 레이캐스트가 답하는 것은 ②뿐이다.
5/5로 통과하고도 광원에서 9m 밖이라 화면에서는 아무것도 안 보인 이상현상이 있었다 —
**통과해도 스크린샷을 한 장 본다.** 프롭을 대량 추가한 뒤에는 반드시 돌린다.

## 골목의 치수 (알고 쓰면 되는 사실)

금지 목록이 아니라 재료의 크기다.

| | |
|---|---|
| 구간 36m × 통행 폭 ±3m × 벽 높이 7m | 좌우 여유가 2~3m뿐 |
| 직진뿐, 갈림길 없음 (출구 = 끝벽 중앙 개구부 반폭 1.4m) | 길찾기·미로는 애초에 다른 게임이다 |
| 구간 전환 = 다리 밑 터널 한가운데의 암흑 | **구간을 넘어 이어지는 존재는 시스템이 지운다** |
| 광원은 구간당 가로등 하나 (+ 테마별 자체 광원) | 밝은 곳이 곧 무대다 |
| 그림자 렌더링 없음 · 반사 없음 | 그림자·반사상을 단서로 쓸 수 없다 |
| 구간 3(놀이터)은 펜스와 벽 사이가 0.85m | 실물 프롭이 못 들어간다. 담장 쪽으로만 늘린다 |

**모바일 화면에서 3초 안에 알아볼 수 있는가**가 명확성의 기준선이다
([responsive-design.md](./responsive-design.md) §6).

⚠ **매달린 실루엣은 법적 준수 항목이다** (자살예방법 — [commercial.md](./commercial.md)
표현 수위의 법적 하한). 현행 빌드의 유혈은 흔적까지만 — 핏자국·끌린 자국이다.

## 데이터 스키마 (`src/data/anomalies.json`)

```jsonc
{
  "id": "H-001",            // 이 문서 표의 ID와 일치
  "night": 1,               // 등장 시작 밤
  "segment": 1,             // 배치 구간 1~5 / 0 = 전 구간 (스폰 앵커 랜덤)
  "effect": "blood_trail",  // world/effects.ts 핸들러 키 = ?a= 디버그 키
  "outboundOnly": true      // 선택 — 귀갓길에 보이지 않는 사물이면 지정
}
```

**새 설계에서 사라지는 필드 셋**:

| 필드 | 왜 사라지나 |
|---|---|
| `rule` (`gaze`/`avert`) | 판정이 없으니 대응 구분도 없다 |
| `untilNight` | 규칙 배신 전용 필드였다 |
| `reveal` | "무엇이 이상했는지" 사후 자막 — **놓침이라는 개념이 없어졌다** |

`category`(OBJ/HUM/LGT/…)는 남긴다. 판정에는 안 쓰지만
**분포를 보는 눈**으로는 여전히 쓸모 있다 (형체만 다섯 구간에 깔리면 단조로워진다).

**선택 로직** — 현재 구간·현재 밤으로 풀을 거르고, 직전 이상현상은 제외한다(연속 방지).
첫 밤 첫 구간은 정상으로 두어 **비교 대상**을 먼저 준다.

## 추가하는 절차

1. **무엇을, 어디에** 정한다 — 위 "잘 듣는 것"에서 고르고, 분포의 구멍을 본다
2. `world/effects.ts`에 핸들러를, `anomalies.json`에 한 줄을 더한다
3. **보이는지 확인한다** — `?a=<effect>` + `occlusion()` 여러 지점 + **스크린샷 한 장**
4. `scripts/verify.mjs`의 cases에 등재하고 이 문서 표에 줄을 더한다

**코드를 열어야 하는 것은 2번의 핸들러 하나뿐이다.** 그 밖에 판정·밸런스·스테이지 파일을
건드려야 한다면 설계가 어긋난 것이니 멈추고 본다.

## 밸런싱

이상현상이 늘어남을 직접 부르지 않으므로 **`balance.ts`의 모델은 이상현상과 무관해졌다.**
남은 변수는 둘뿐이다 — **얼마나 자주 멈추게 되는가**와 **한 번에 얼마나 오래 멈추는가.**

- 구간당 등장 수를 올리면 멈출 기회가 늘고, 밤이 길어진다
- 알아보기 쉬운 것은 짧게 멈추게 하고, 애매한 것은 길게 멈추게 한다.
  **애매함이 곧 난이도다** — 판정을 어렵게 만들 필요가 없다
- ⚠ 이 수치들은 **가정으로 잡지 않는다.** 헤드리스 주파로 "실제로 몇 초 멈췄는가"를
  재서 정한다 ([workflow.md](./workflow.md) — 실측 규칙)
