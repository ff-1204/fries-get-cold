# 이상현상 설계

**이상현상 = 학습된 정상의 미세 위반.** 플레이어가 "평소 상태"를 알고 있는 사물이
조금 어긋나 있을 때 가장 무섭다 ([fear-cognition.md](./fear-cognition.md) §1 예측 오류).
그래서 모든 이상현상은 **구간 테마에 항상 존재하는 사물**에만 걸 수 있고,
정상 상태가 먼저 충분히 노출되어야 한다.

- 콘텐츠 소스: **`src/data/anomalies.json`** (스키마는 아래) — 이 문서의 표는 설계·현황판
- 확인 방법: URL에 `?a=<effect>` — 해당 구간에 도달하면 강제 등장 (`?a=none` = 항상 정상)
- **2026-08-02 컨셉 전환 노트**: 판정 오답의 결과는 실패(암전)가 아니라 **접힘**(구간 반복 +
  남은 거리 증가) — v0.4.0에서 구현 완료 (game.md 결정 기록). 이상현상 정의·배치 원칙·현황판은
  그대로 유효하며, `night` 해금 축에 병행할 **깊이 해금**은 M3 확장(30종+)에서 추가 예정

(`world.ts SPAWN_ANCHORS` — 통행 한계 안쪽·가로등 시야권)에서 고른다.

## 이상현상 추가하는 법 (3단계)

1. **이 문서의 표에 행 추가** — 정상→이상, 분류, 등장 밤. 아래 원칙 4개를 먼저 통과시킨다.
2. **`src/data/anomalies.json`에 데이터 추가.** 기존 effect(사물 상태 변화)를 재사용하면 여기서 끝.
   새로운 시각 변화가 필요하면 `src/world.ts`에 effect 핸들러 1개 추가
   (구간 테마에 사물이 없다면 테마 그룹에 '정상 상태'부터 만든다).
3. **`?a=<effect>`로 직접 확인** — 명확성 자가 테스트: "정상/이상 스크린샷 두 장을 나란히
   보여주면 3초 안에 찾는가?" + 아래 배치 3원칙 점검.

## 설계 원칙 (위반하면 추가 금지)

1. **명확성** — 보면 "아!" 하고 무릎을 쳐야 한다. 픽셀 틀린그림찾기 금지.
   - 공정: 셔터가 열림, 그네가 혼자 흔들림, 양쪽 다 빨간불
   - 불공정: 벽돌 개수가 다름, 원경의 미세한 색 차이
2. **일상성** — 한국의 밤 골목에 실제로 있을 법한 사물의 어긋남. 기괴한 크리처보다
   "아까랑 그림자 방향만 다른 사람"이 더 무섭다.
3. **1회 학습** — 한 번 당한 이상현상은 다음부터 반드시 알아볼 수 있어야 한다.
4. **깜놀 총량제** — 점프스케어형은 전체의 10% 이하, 밤 4~5에만.

## 배치 3원칙 (2026-07-29 — A-013 사례에서 도출)

이상현상은 "존재"가 아니라 **"보이는 것"** 이 구현 완료 기준이다.

1. **광원 안쪽** — 구간 포인트라이트(가로등) 사거리 안에 둔다. 안개(FogExp2)는 거리 제곱으로
   먹히므로, 구간 후반(70% 이후)에 어두운 색 사물을 두면 사실상 존재하지 않는 것과 같다.
2. **관찰 시간 확보** — 구간 출구(끝 벽 개구부)에서 최소 10m 앞에 배치. 출구 바로 옆에
   두면 보고 판단할 틈이 없다.
3. **실루엣 대비** — 벽 색(`#20263a`대)과 명도가 겹치는 사물은 안 보인다. 정상/이상 상태의
   차이는 각도 몇 도가 아니라 **실루엣이 바뀌는 수준**이어야 한다.
   (스스로 빛나는 이상 — 셔터 안의 불, 켜진 간판, 빨간불 — 이 가장 확실하다)

## 데이터 스키마 (`src/data/anomalies.json`)

```jsonc
{
  "id": "A-004",            // 이 문서 표의 ID와 일치
  "night": 1,               // 등장 시작 밤 (해금)
  "segment": 2,             // 배치 구간 1~5 (테마 사물 고정) / 0 = 전 구간 (스폰 앵커 랜덤)
  "category": "OBJ",        // OBJ|LGT|TXT|HUM|SPC|SND|MTA (아래 분류 체계)
  "effect": "laundry_open", // world.ts 핸들러 키 = ?a= 디버그 키
  "reveal": "…세탁소 셔터가 반쯤 열려 있었다. 안이 밝았다.",  // 실패 직후 암시 문구 (공정성)
  "outboundOnly": true      // 선택 — 귀갓길에 보이지 않는 사물(튀김집 간판 등)이면 지정 (밤 5 한정 귀갓길 대비, 공정성)
}
```

TXT 계열은 캔버스 텍스트 렌더(world.ts `canvasTex`)로 정상/이상 텍스처 쌍을 만들어 교체한다.
시스템 폰트만 사용 (오프라인 단일 파일 빌드 유지 — 웹폰트 로드 금지).

선택 로직(main.ts rollSegment): 현재 구간·현재 밤으로 풀을 거르고, 직전 이상현상은 제외
(연속 등장 방지). 밤 1 첫 구간은 항상 정상, 밤 1 편도에 최소 1회 보장 (온보딩).

## 분류 체계와 해금 밤

| 분류 | 코드 | 설명 | 해금 | 예시 |
|---|---|---|---|---|
| 사물 | OBJ | 정적 사물의 상태 변화 | 밤 1 | 셔터, 그네, 공, 입간판, 우산 |
| 조명 | LGT | 빛의 어긋남 | 밤 1 | 센서등, 간판, 신호등, 가로등 깜빡임 |
| 텍스트 | TXT | 글자·문서의 변화 | 밤 2 | 전단지 번호, 시세표, 간판 오탈자 |
| 인물 | HUM | 사람 형태의 어긋남 | 밤 3 | 같은 자리의 실루엣, 그림자 방향 |
| 소리 | SND | 청각 단서 (시각 확인 필요) | 밤 3 | 늦게 오는 발소리, 한 박자 늦는 메아리 |
| 공간 | SPC | 지형·구조의 어긋남 | 밤 4 | 늘어난 골목, 사라진 모퉁이 |
| UI | MTA | 메타/UI 어긋남 (아껴 쓰기) | 밤 4 | 구간 카운터 역행, 자막 오염, 거짓 힌트 |

## 규칙형 괴담 (이상현상과 별개 축 — 밤 2부터)

명시적 규칙. 힌트 텍스트 + 위반 조건 + 결과로 구성. M2 힌트 시스템에서 구현.

```jsonc
{
  "id": "R-001",
  "night": 2,
  "hintSource": "convenience_door",   // 힌트가 붙는 위치
  "hintText": "오늘은 정류장에 앉아 계신 분께 인사하지 마세요.",
  "violation": "interact:bus_stop_person",
  "result": "reset_to_start",
  "authoredAt": "today"               // 밤 4: 'yesterday' 힌트 = 만료된 규칙
}
```

## 밸런싱 메모

- 구간당 이상 발생 기본 확률 40% + 새벽이 깊을수록 상승 (`config.ts CONFIG`).
  수치는 플레이테스트로 조정
- 같은 이상현상 연속 등장 금지 (구현됨 — 접힘 반복 구간에서 특히 중요).
  목표: 한 세션 1회 초과 재사용 금지 (풀이 커지면)
- 지적 비용 (2026-08-02, v0.5.0): 빈 지적 = 깊이 +1 (즉각 가로등 감광), 연타는
  쿨다운 0.6초로 차단. 접힘 = 깊이 +2. 깊이 한계 6 = 입구 리셋 —
  접힘 3회 / 빈 지적만 6회. `npm run verify:sim`(모델)·`verify:balance`(E2E)로 검증됨
- 범주 로테이션: 같은 범주(OBJ/LGT/…)의 연속 등장을 피한다 (fear-cognition §4 습관화) — M3 예정
