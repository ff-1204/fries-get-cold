# 시각 마감 / 체감 품질

정적 호스팅(GitHub Pages)에서도 **싸 보이지 않는 호러**를 만들기 위한 마감 규칙.
"싼티"는 성능이 아니라 연출·비주얼 마감의 문제다 — 그리고 호러 장르에서 싼티는
곧 **공포의 죽음**이다 (무서워야 할 장면에서 웃음이 나온다).

> **상위 원칙**: 이 문서는 [design-principles.md](./design-principles.md)의 하위 실천 지침이다.
> 마감이 화려해도 UI의 정직함(§3)·표현 수위 원칙(design-principles §1-1)을 해치면 안 된다.

---

## 1. 미학-사용성 효과 — 첫인상에 예산 집중

"예뻐 보이면 더 잘 만든 게임이라고 느낀다." 호러에서는 "분위기 있어 보이면 더 무섭다."

**적용:** 마감 예산 1순위는 ① 타이틀 게이트(첫 화면) ② 퇴근길에 처음 걷는 골목(첫 공간)
③ 매 밤의 귀가 연출(집 도착). 플레이어의 기억을 지배하는 세 장면이다.

## 2. 주스(Juice) — 호러판은 "절제된 반응성"

캐주얼 게임의 주스(통통 튀는 팝, 파티클)는 호러에서 독이다. 우리의 주스는 **무게감**이다.

- 모든 입력에 즉각 반응하되, 반응은 조용하게: 발소리, 게이지의 부드러운 변화, 문구 페이드.
- 팝·바운스 이징 금지. 등장/퇴장은 느린 페이드와 슬로우 이즈만.
- 화면 흔들림 금지(멀미 + 값싼 공포). 카메라는 항상 안정적으로 — 흔들리는 건 세계여야지 카메라가 아니다.
- **60fps 유지가 최우선 품질 신호** (모바일 30fps 하한 — [responsive-design.md](./responsive-design.md)).
  프레임 드랍은 몰입 파괴 = 공포 파괴.

## 3. 색 — 제한된 팔레트 (60-30-10)

어둠 60% / 한색(불안) 30% / 웜(안전·목표) 10%. **웜 컬러가 희소해야 집 창문·가로등이 목표로 빛난다.**

| 역할 | HEX | 용도 |
|------|-----|------|
| 배경/어둠 | `#0a0e1a` | 밤하늘·안개 (순수 검정 금지 — OLED) |
| 표면(벽·바닥) | `#181c28`–`#232838` | 골목 구조물 |
| 텍스트 | `#d8d8e0` | HUD·자막 |
| 서브텍스트 | `#8b90a8` | 보조 정보 |
| **온기(안전·목표)** | `#ffb23e` | FF-1204 간판, 방 창문(집), 가로등, 버튼 |
| **이상(어긋남)** | `#7a1010` 계열 저채도 적 | 이상현상 시그널 전용 |
| 정적 강조 | `#7a5cff` | 깊은 밤(깊이 심화) 연출 보조 |

- **의미색 고정**: 웜 = 안전/목표, 저채도 적 = 어긋남. 이 매핑은 게임 전체에서 뒤집지 않는다.
  (밤 4~5의 "따뜻한데 불길함" 연출은 예외적 배신으로 아껴 쓴다 — 알아챌 수 있는 단서를 남긴다)
- **남은 구간 카운터는 HUD 텍스트색** — 절제한다. 카운터는 숫자 자체가 공포를 담당한다.
- 원색·고채도 남발 금지. 이상현상조차 채도를 낮춘다 (야하게 빛나는 호러는 싸다).

### ⭐ 예외 하나 — 퇴근길은 해 넘어간 뒤의 골목이다 (v0.11.52~54)

**목표는 '따뜻함'이 아니라 '밝고 연함'이다.** 레퍼런스(해 질 녘 한국 골목 사진 셋)를
분석해 보니 공통점은 주황이 아니었다:

| | 레퍼런스 | 이 구간이 하는 것 |
|---|---|---|
| 하늘 | 파스텔 **분홍·라벤더** | 그라데이션 돔 + 소실점의 해 |
| 벽 | 밝은 **크림·미색** | 밤의 색을 색상 유지·**밝기 상향**·채도 하향 |
| 대비 | 하이키·저대비, 다만 **명암은 살아 있다** | 키(해) 4.6 vs 필(앰비언트) 1.8 |
| 온기 | **한 점만** (가게 문·편의점 간판) | FF-1204 + 가로등. 부스는 한색 형광 |
| 하늘 | **전선이 가른다** | 전신주 4개 + `LineSegments` 전선 |

⚠ **네 번 틀리고 잡았다** — 순서대로: ① 해를 낮춰 어두워짐 ② 재질 밝기+조명을 함께 올려
화이트아웃 ③ 채도만 낮췄더니 세피아 ④ 색상 혼합률을 낮췄더니 **올리브색**.

⭐ 배운 것 셋:
1. **조명만으로는 안 된다** — 기본색이 한색이면 재질을 바꿔야 한다
2. **따뜻함은 색상, 구조는 밝기** — 둘을 같이 만지면 둘 다 잃는다
3. ⚠⚠ **'덜 주황'은 채도로 만든다.** 색상환을 선형 보간하면 파랑(0.62)→주황(0.075) 사이의
   **초록(0.33)을 지나간다** — 혼합률을 낮추는 순간 벽이 올리브가 된다

### 이전 절 (v0.11.52 최초 노을)

위 팔레트는 **밤의 것**이다. 첫날 퇴근길 튜토리얼은 게임에서 유일하게 밝은 구간이고,
여기서는 **웜을 아낌없이 쓴다.** 밤의 희소한 온기와 낙차를 만드는 것이 튜토리얼의 존재 이유다.

| 역할 | HEX | |
|---|---|---|
| 하늘 (천정→지평선) | `#414369` → `#f2b264` | 그라데이션 돔. **위는 식은 보랏빛** |
| 대기(안개) | `#c59782` | 하늘보다 옅고 탁하게 — 먼 곳이 이 색으로 물러난다 |
| 해 | `#ffa64a` · 세기 5.4 · 위치 (11, 6, 3) | 크게 기울어 든다 |
| 표면 | 밤의 색을 색상만 호박(0.075)으로 돌린 것 | `runtime.ts duskOf` |
| **가로등** | `#ffb463` · 세기 7.5 | 밤(26)의 1/3도 안 된다 |
| **정류장 부스** | `#ffcb96` · 세기 5 | 밤에는 한색 형광(`#bcd0ea`) |
| **다리 밑 터널** | `#ff9a4c` | 나트륨등 — 밤에는 한색(`#bcc6d8`) |
| **전조등** | 세기 11 | 밤은 26 |

⭐ **해가 남아 있는데 등이 먼저 들어온다** — 그 짧은 시간이 퇴근길의 정서다.
여태 퇴근길에는 가로등·부스등·터널등이 전부 꺼져 있었다(밝으니 필요 없다는 판단이었다).
**필요해서 켜는 것이 아니라 시간을 말하려고 켜는 것이다.**
⚠ 밤의 1/3도 안 되게 건다 — 세면 밤처럼 보이고, 그러면 튜토리얼이 만들 낙차가 사라진다.

세 가지를 실측으로 배웠다:

1. **조명만으로는 따뜻해지지 않는다.** 기본색이 한색이면 웜 조명을 아무리 세게 걸어도
   진흙빛에서 멈춘다 — **재질의 색 자체**를 돌려야 한다
2. ⚠ **따뜻함은 색상에서 오고 구조는 밝기에서 온다.** 재질 밝기까지 같이 올렸더니
   화면 전체가 같은 겨자색으로 뭉개져 벽·바닥·프롭이 구분되지 않았다
3. ⭐ **위쪽을 식혀야 아래가 따뜻해진다.** 하늘 천정에 보랏빛 남색을 두는 것이
   따뜻함을 깎지 않고 키운다 — 전부 주황이면 노을이 아니라 세피아 사진이다

## 4. 조명·안개 — 3D 호러의 핵심 마감

- 광원 규칙: 앰비언트(저강도) + 달빛 방향광 1 + 구간당 포인트라이트 1~2(가로등·간판)만.
  광원 수가 곧 성능이자 스타일이다.
- 안개(FogExp2) 밀도는 "다음 구간이 어렴풋이 보이는" 수준으로 고정 — 완전히 가리면 답답하고
  다 보이면 무섭지 않다. 밤이 깊을수록 미세 증가([affective-design.md](./affective-design.md)).
- **밝기의 원칙 (2026-08-02 재조정, v0.8.1)**: 공포는 어둠의 절대량이 아니라 **대비**에서 —
  기본 노출·앰비언트 바닥은 "벽·바닥 실루엣이 항상 읽히는" 수준까지 올리고, 무서움은
  웜/한색 대비·안개·감광 사다리(깊이)가 담당한다. "잘 안 보여서 무섭다"는 설계 실패로 간주.
- **실루엣 가독성**: 이상현상은 어두워도 3초 안에 식별 가능해야 한다
  ([anomalies.md](./anomalies.md) 명확성 원칙과 동일 조항). 분위기를 위해 판정을 어둡게 만들지 않는다.
- 밝기 슬라이더 제공 ("이 문구가 겨우 보일 정도로" 패턴 — responsive-design §5).

## 5. 형태·정렬·아트 디렉션

- **하나의 아트 디렉션 끝까지**: 로우폴리 + 안개 + 포인트라이트. 에셋 스토어 혼합,
  포토리얼 텍스처 끼워넣기 금지 — 스타일 짜깁기가 가장 싼티하다.

### ⭐ 로우폴리의 품질은 어디서 나오는가

텍스처 의존도가 낮은 대신 **빛과 색이 전부**다.

1. **Directional(직사광) ↔ Ambient(환경광)의 대비.** 필이 세면 하이키가 아니라 **평면**이 된다 —
   퇴근길에서 앰비언트를 낮추고(1.8) 해를 올려(4.6) 명암을 되살린 것이 그 교정이다
2. **파스텔 조합.** 채도를 올리는 순간 로우폴리는 장난감이 된다. 시간대 보정 상한 0.24
3. **`flatShading: true`** — 폴리곤의 각진 면을 살린다.
   ⚠ **`BoxGeometry`에는 무의미하다**: 박스는 면마다 법선이 이미 갈라져 있다.
   값이 나오는 것은 **구·원뿔 계열**뿐이다 — 형체의 머리, 두개골, 눈, 담 너머 수목, 공, 우산 갓.
   ⚠ 하늘 돔(`MeshBasicMaterial` + 그라데이션)에는 걸지 않는다: 조명을 안 받아 효과가 없고,
   설령 받아도 하늘에 각진 면이 생기면 그게 곧 결함이다

### 표면 텍스처를 쓰는 법 (v0.11.52)

⚠ 위 금지는 **짜깁기**를 막는 것이지 텍스처 자체를 막는 것이 아니다.
벽·바닥이 민짜라 빛이 걸릴 데가 없었고, 그래서 노을이 세피아에서 멈췄다.

| 하는 것 | 안 하는 것 |
|---|---|
| 캔버스 생성, 256px, 회색조 | 이미지 파일, 4K, 컬러맵 |
| **밝기만** — 색은 `material.color`가 낸다 | 텍스처에 색을 넣는 것 (팔레트가 둘이 된다) |
| 진폭 0.06~0.15 | 0.18+ — **큰 검은 번짐**으로 읽힌다 (실측) |
| 주기적 노이즈(이음매 없음) | 일반 노이즈 — 36m 벽에 경계선이 여섯 번 나온다 |
| — | ⚠ **노멀맵**. 그림자 렌더링이 0이라 면 법선만으로 음영을 내는데, 가짜 요철이 그 평평함을 깬다 |

### 골목을 채우는 것들 (v0.11.54~55)

| | 만드는 법 | 왜 |
|---|---|---|
| **전선** | `LineSegments` 하나 · 처짐(포물선) 필수 | 한국 골목의 서명. 드로우콜 1개. 곧은 직선은 철사로 보인다 |
| **소실점의 해** | 하늘 텍스처에 빛무리 | 레퍼런스 3/3이 소실점에 빛을 갖고 있었다 |
| **초록** | 벽 밑 화분 + **담 위로 넘어온 나무** | 사람이 사는 동네의 표시 |

⚠ **평평한 면에 붙인 식물은 붙은 것으로 안 읽힌다.** 벽면 담쟁이를 두 번 시도해
둘 다 '벽에 붙인 초록 상자'였다. 로우폴리에서 식물은 **하늘을 배경으로 한 실루엣**일 때
가장 확실하게 식물이 된다 — 담 위·펜스 위·지붕 위에 얹는다.

⚠ **잎은 시간대 보정에서 제외한다**(`keepColor`) — 색상이 끌려가면 화면에서 유일한
채도 높은 초록이 사라진다.

⭐ **텍스처는 이상현상을 덜 보이게 만든다.** 가시성은 대상과 **둘레 배경**의 휘도 차인데,
배경에 무늬가 생기면 그 차가 줄어든다 — 아스팔트에 골재를 넣자 길 건너 형체(H-014)의
대비가 15.6 → 8.9로 깎였다. 진폭을 올리기 전에 `verify:visible`을 돌린다.
- HUD 간격은 8pt 그리드, 라운드 코너 일관(8px), 그림자는 텍스트 섀도 1단계만.
- 폰트는 **1종**(Pretendard 계열), 굵기로만 위계. HUD 크기는 `clamp()`로 반응형.

## 6. 카피 톤 — 문구도 마감이다

- 게임 내 모든 텍스트는 story.md의 목소리로: 짧고, 마르고, 담담하게.
- 금지: 느낌표 남발, "당신은 죽었다!"류 호러 클리셰, 광고식 문구("무료", "지금 바로").
  - **예외 하나 — 첫 시작 버튼 "퇴근하기!"** (v0.11.26). 게임 안에는 느낌표가 없고
    여기 딱 한 번만 쓴다. 신장개업 튀김집·방문 도장과 같은 **유머 앵커**이자,
    가벼운 퇴근 기분과 그 뒤에 오는 밤의 낙차를 벌리는 장치다. 되돌리지 말 것.
- 실패 문구조차 톤 유지: "…침대에서 눈을 뜬다." (공포를 설명하지 않는다)
- 물결표(~) 금지 — 범위는 엔대시(–)로: `1–2분`.

## 7. 모션 기본값 (호러 이징 표)

| 상황 | 방식 | duration |
|------|------|----------|
| 암전(실패·전환) | linear/ease 페이드 | 800–1200ms |
| 오버레이 등장 | opacity 페이드 | 600–900ms |
| HUD 문구 | opacity 페이드 | 600ms in / 2.6s hold |
| 남은 구간 카운터 +1 (늘어남) | 페이드 교체 — 팝 금지, 조용히 바뀌어 있는 게 더 무섭다. 단 사운드 드랍 병행으로 인지 보장 | 600ms |
| 가로등 깜빡임 | 스텝(트윈 없음 — 형광등은 튄다) | 패턴 정의 |
| 이상현상 등장 | **트윈 없음. 이미 그렇게 있어야 한다** | — |

마지막 줄이 이 게임의 마감 철학이다 — 이상현상이 "짠" 하고 나타나면 싸구려 유령의 집이 된다.
플레이어가 모퉁이를 돌았을 때 **이미 어긋나 있는 것**이 무섭다.

## 8. 지각된 성능

- 시작 게이트("퇴근하기!")가 곧 로딩 화면 — 클릭 전에 에셋 로드를 끝낸다.
- 입력 반응 400ms 이내(Doherty). 씬 전환은 페이드로 하드 컷 방지.
- 에셋 예산은 [development.md](./development.md) 성능 예산 표를 따른다.

## 체크리스트 (릴리스 전 "싼티" 점검)

- [ ] HUD 요소끼리/자막과 겹치지 않는가 (좌표 검산)
- [ ] 첫 화면(타이틀 게이트)이 분위기 있는가
- [ ] 색이 팔레트 안에서만 쓰였는가 — 특히 웜 컬러가 10% 이하로 희소한가
- [ ] 이상현상이 어두운 화면에서도 3초 내 식별되는가
- [ ] 이상현상에 등장 트윈이 없는가 ("이미 그렇게 있다")
- [ ] 카메라 흔들림·팝 이징이 없는가
- [ ] 60fps(PC)/30fps(모바일)로 부드러운가
- [ ] 실패·전환이 페이드로 처리되는가 (하드 컷 없음)
- [ ] 모든 문구가 담담한 톤인가 (느낌표·클리셰 검사)
