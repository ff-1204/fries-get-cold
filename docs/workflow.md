# 개발 워크플로

이 프로젝트의 작업 절차. 1인 개발 규모에 맞게 단순하게 유지한다.

---

## 파이프라인

```
구현 → 검증 → 문서 → 커밋 → (릴리즈면) 배포
```

1. **구현** — 콘텐츠는 `src/data/` JSON에, 로직은 시스템 쪽에 있다
2. **검증** — 아래 '무엇을 언제 돌리나'. 코드가 바뀌었으면 `npm run build:local`로
   `play-local.html`도 재생성한다
3. **문서** — 어느 문서인지는 CLAUDE.md의 문서 맵
4. **커밋** — Conventional Commits + 한국어 제목.
   버전은 package.json이 아니라 CHANGELOG.md와 커밋 제목에 적혀 있다

### 무엇을 언제 돌리나

| | 무엇을 볼 때 | 무엇 |
|---|---|---|
| `npm run build` | 타입까지 통째로 | 타입 검사 포함 |
| `npm run verify:sim` | 깊이 모델 | 10건, <1초 |
| `npm run verify:balance` | 속도·공간 | E2E 6케이스 |
| `npm run verify:shots` | 시각 변경 | 이상현상 쌍 + 테마 + 늘어남 |
| `npm run verify:play` | 흐름·전환 | 첫 방문 → 튜토리얼 → 밤 1 → 집 → 밤 2 |
| `__fries.occlusion()` | 프롭 추가 후 | 이상현상이 가려지지 않는지 |
| **직접 걷기** | 구간이 바뀌었을 때 | 자동 검증은 "재밌는가"를 답하지 못한다 |

## 플레이테스트

- 밤 하나가 완성되면 처음부터 걸어 본다
- 외부 테스터에게 조작법만 알려주고 규칙을 알려주지 않으면
  무설명 학습이 되는지가 드러난다
- 볼 만한 것: 오판 지점 · 리셋 후 이탈 여부 · 이상현상별 발견 시간 · 웃은 지점

## 릴리즈

1. CHANGELOG에 `vX.Y.Z` 절을 쓰고, 현행 문서(spec·stages·anomalies)를 실빌드와 대조한다
2. `git tag -a vX.Y.Z` — 태그 메시지에 릴리즈 노트를 담는다
3. `git push origin main` — **pre-push 훅이 빌드 + gh-pages 발행을 자동 실행한다**
4. 태그를 올린다: `SKIP_DEPLOY=1 git push origin vX.Y.Z` (main은 이미 배포됐다)
5. **라이브 URL의 에셋 해시가 방금 빌드와 같은지 확인한다** (Pages 반영에 1분 남짓)
6. 모바일 실기기 1회 확인

## 이 프로젝트에서 반복적으로 효과가 있었던 것

- **공간 정합성은 눈이 제일 빠르다.** 실플레이 지적이 전부 실제 결함이었다 —
  뒤돌아보니 있으면 안 되는 건물 / 차가 다음 구간까지 따라옴 / 신호등이 둘 다 같은 쪽을 봄 /
  되돌아가면 암흑 막다른 끝. "뒤돌아보기 · 구간 넘기기 · 되돌아가기" 세 동작에서 대부분 드러났고,
  자동 검증으로는 잘 안 걸렸다
- **막고 싶을 때 벽보다 연출이 잘 먹혔다.** 되돌아가기 → 골목이 돌려세운다,
  순간이동 → 다리 밑 터널
- **자막은 2줄 이내가 잘 읽혔다.** 길게 설명하면 사고가 되고 짧게 흐리면 꿈이 된다.
  정보를 늘리는 대신 위치를 나누면 걸음이 문장을 끈다
- **사람이 직접 하는 플레이가 계속 뒤로 밀렸다.** `verify:play`가 끝에서 끝까지
  "동작하는가"는 답하게 됐지만, "재밌는가"는 여전히 아무도 확인하지 않았다.
  무설명 학습이 되는지, 어디서 웃는지, 어디서 그만두고 싶은지는 거기서만 나온다

## 배운 것 (실수 → 기록)

겪은 실수를 "무엇을"이 아니라 **"어떻게"**로 남긴 자리다.
사건의 상세는 CHANGELOG에 있다.

### 설계·배치

| 관찰 | 왜 |
|---|---|
| 이상현상이 보이는 조건은 셋이었다 — 광원 안쪽 · 판정 10m 앞 · 실루엣 대비 | 입간판이 사실상 안 보였다 |
| 눈높이(1.2m+) 구조물은 벽면과 평행일 때, 통행 한계(x±2.6) 안쪽일 때 문제가 없었다 | 통로에 수직으로 선 슬랩이 막힌 벽처럼 보이고 카메라가 관통했다 |
| 프롭은 **구간 전체 길이**를 채웠는지 본다 | 사람은 눈에 띄는 앞쪽부터 배치하게 되고, 스크린샷을 '중반'에서만 찍으면 뒷부분은 영영 안 걸린다 |
| **위치로 도는 연출은 "그 위치에 그것이 실제로 있는가"를 조건에 넣는다** | 좌표 조건(`z < -L`)은 지형이 바뀌어도 참이라, 숨긴 지형의 연출만 남는다 (도착지 코앞이 새까매졌다) |
| **결정은 전제와 함께 기록하고, 전제가 사라지면 다시 연다** | "지금은 X가 없으니 Y로 한다"에 X를 명시해야 X가 생겼을 때 검색에 걸린다. 새 장소·새 시스템을 넣는 커밋에서는 "이게 없어서 우회했던 결정"을 훑는다 |
| 무봉합 이음매가 특정 지점의 암흑에 기대고 있다면, 그 지점은 **지나가는 순간에만 존재**해야 한다 | 터널 한가운데를 자유롭게 오갈 수 있어 암흑 막다른 끝이 생겼다 |
| **구간 수명 오브젝트는 전환 시 명시적으로 거둔다** + 매 프레임 가시성 가드 | 한 겹으로는 새어나간다 (차가 다음 테마까지 따라왔다) |
| 시간 제한이 있는 안전 규칙은 **유예 구간이 소요 시간보다 길어야** 공정하다 | 점멸 2.5초 ≥ 횡단 2.1초 |
| **퇴역 effect의 `reset`도 매 구간 돈다** — 대상 물건을 다른 것으로 바꿀 땐 핸들러를 함께 비운다 | `applyAnomalies`가 전 effect를 리셋하므로, 발동하지 않는 `shop_typo`가 매 구간 현수막 그림을 옛 간판 텍스처로 덮고 있었다 |
| **같은 것이 두 곳에 필요하면 소유를 공용으로 올린다** — 복제하지 않는다 | 현수막이 테마 4의 자식이라 먹자골목에서 안 보여 하나를 더 만들었다. 둘이면 "저기가 거기다"가 깨진다 |
| **배치를 가리키는 색인은 하드코딩하지 않고 조건을 그대로 계산한다** | `OPEN_I = 2`가 박혀 있어 배치를 바꿀 때마다 손으로 확인해야 했다. 계산이면 못 찾을 때 −1이 되어 검증이 실패로 잡는다 |
| **머리 위를 채우기 전에 "위가 닫혀 있는가"를 본다** | 아케이드 레퍼런스를 열린 하늘 구간에 옮겨 골조·덕트·실외기를 달았다가 전부 걷어냈다 — 그 하늘이 이 구간의 자산이었다 |
| **밀도는 바닥이 아니라 벽에서 만든다** | 바닥 물건은 시야 하단에 계속 들어와 지겹고, 통행선을 좁히고, 무릎 아래라 실루엣이 없다. 같은 노력을 벽에 쓰면 붐비지 않으면서 밀도가 오른다 |
| **같은 일을 하는 계통은 하나만 둔다** | 옛 가로 전구줄(y 3.95)과 새 종축(y 4.72)이 거의 같은 높이에서 격자로 얽혔다 |
| ⭐⭐ **배경 프롭은 이상현상의 광원을 나눠 쓰지 않는다** — 새 물건을 놓기 전에 "이 빛이 누구 것인가"를 본다 | 재개발 고지문을 셔터 옆에 붙였더니 **밤 화면에서 제일 밝은 물건**이 됐다. 그 자리는 H-008·H-015가 '광원 안쪽'을 조건으로 두 번씩 옮겨 가며 맞춘 배치였다 — 이상현상이 경쟁 상대를 얻으면 실측이 내려간다 |
| ⭐⭐ **'보이는 것만 바꾸는' 장치는 광원·판정과 반드시 어긋난다** — 세계의 절반만 뒤집을 수 있으면 뒤집지 않는다 | `setThemeMirror`가 테마만 x 반전했는데 가로등·전신주·현수막은 공용이라 안 뒤집혔다. 부스가 광원 반대편으로 가서 형체가 어두워졌고, 원인을 대상 쪽에서 찾느라 창백한 손까지 붙였다. **거울을 지우자 26.3→105.0 · 7.4→44.5** — 지운 것만으로 올랐다 |
| ⭐ **자국·얼룩은 밝은 쪽이 아니라 어두운 쪽으로 만든다** | 뜯긴 간판 자리를 "안 바래서 밝다"로 칠했더니 노을 앰비언트(2.8)에 씻겨 흰 판이 됐다. 실제로 남는 것은 접착제·녹물·때다 — **어두우면 두 시간대 모두 자국으로 남는다** |
| ⭐⭐ **밀도를 넣기 전에 "비출 것이 있는가"를 본다** — 어두운 구간의 처방은 프롭이 아니라 **그 장소의 제 빛**이다 | 테마 2는 v0.11.34에 셔터 다섯을 넣고도 가로등을 지나면 여전히 암흑이었다. 자판기 하나를 켜자 같은 프롭이 보이기 시작했다 |
| ⭐ **국소화는 '짧게'가 아니라 '그 물건에 맞게'다** — 길이를 통일하지 말고 대상에서 파생시킨다 | 구간 전체를 달리던 보도 단차를 가게 앞으로 줄이면서 길이를 셔터 폭으로 통일했더니, 더 깊은 세탁소 앞 단차가 가로등에 0.26m 모자라 H-019의 배경이 빠졌다 (7.3 → 6.7) |
| ⚠ **실측값의 흔들림 폭을 먼저 알고 나서 차이를 해석한다** | H-019가 0.5 내려간 원인을 지하 계단 어둠으로 짚고 고쳤는데 값이 안 움직였다. 같은 빌드에서 H-004가 14.1/14.3/14.4로 나온다 — **±0.3 안의 차이는 원인을 찾을 수 있는 신호가 아니다** |
| ⭐⭐ **중성화는 휘도를 유지한 채 색상만 돌린다** — 파란 기를 빼는 것이 목적이지 어둡게 하는 것이 아니다 | 두 번 겪었다. 테마 3에서 그네 프레임이 6% 어두워지자 그 위에 앉는 H-005가 52.1 → 49.0으로 따라 내려갔다. 휘도를 맞추자 53.6으로 돌아왔다 |
| ⭐⭐ **하드코딩된 색이 하나라도 남으면 재질 통일이 새어 나간다** — `M`을 만들 때 그 파일의 리터럴을 전수로 흡수한다 | 테마 3의 펜스 13칸 중 4칸이 `M` 선언보다 위에 있어 색을 직접 들고 있었다. `M`만 중성화하자 **같은 펜스가 두 색으로 갈렸고** H-020이 64.1 → 55.8로 내려갔다 |
| ⭐ **담 너머 실루엣은 각도를 먼저 계산한다** — `기울기 = (담 높이 − 눈높이) / 담까지 거리` | 놀이기구가 담에서 2.2m 멀리 서 있어 **완전히 가려져 있었다**(필요 10.9m vs 실제 8.7m). 같은 파일의 H-012 주석이 이미 그 계산을 적어 뒀는데 형체만 옮기고 기구는 그대로 뒀다 — **전제가 같으면 걸린 것을 전부 다시 본다** |
| ⚠ **광원을 더할 때마다 근처 이상현상이 값을 문다** — 세기·사거리로 절충하고 실측으로 확인한다 | 테마 3 뒤쪽 보안등을 앞쪽과 같은 값(6.5·12)으로 켜자 같은 자리의 H-020이 64.2 → 59.9로 내려갔다. 4.2·9로 낮추니 담 위는 그대로 훑으면서 64.2로 돌아왔다 |

### 검증

| 관찰 | 왜 |
|---|---|
| 검증 주행의 성공 조건은 "실패하지 않음"이 아니라 **"의도한 만큼 전진함"** | `phase` 변화만 보면 치임·붙잡힘도 통과로 읽힌다. 테마 3·2·1 스크린샷이 한동안 갱신되지 않고 있었다 |
| 커버리지가 줄면 **조용히 줄지 말고 경고**하게 만든다 | 위와 같은 사고를 다음에는 로그가 잡는다 |
| 가시성 판정은 `object.visible`이 아니라 **조상까지** 확인하고, 레이는 그룹 중심이 아니라 **개별 메시**로 쏜다 | 테마 5개가 같은 좌표를 공유한다. 첫 측정값을 믿었으면 멀쩡한 배치를 뜯어고칠 뻔했다 |
| 프롭을 대량 추가하면 **`occlusion()`을 자동으로 돌린다** | 아홉 개 × 여러 각도를 눈으로 보는 것보다 빠르고 확실하다 |
| ⚠ **가림 검사는 '밝기'를 재지 않는다** — 통과해도 **스크린샷을 한 장 본다** | 배치 3원칙은 ①광원 안쪽 ②관찰 시간 ③실루엣 대비 셋인데, 레이캐스트가 답하는 것은 ②뿐이다. 5/5로 통과한 이상현상이 광원에서 9m 밖이라 화면에서는 아무것도 안 보인 적이 있다 |
| 새 물건을 구조물 사이에 끼울 때는 **주변 프롭의 두께와 높이를 먼저 읽는다** | 셔터면(두께 0.12)·보도 단차(y 0~0.14)에 연달아 파묻혔다. 좁은 틈은 이미 꽉 차 있다 — **통행부 바닥은 언제나 비어 있다** |
| 기존 사물을 '바꾸는' 이상현상은 **원래 것을 숨긴다** | 열린 셔터를 닫힌 셔터 위에 겹쳐 두었더니 닫힌 쪽이 그대로 덮었다 |
| 넓은 면에 **발광을 걸면 빛이 아니라 칠한 사각형**이 된다 | 색만 바꾸고 광원이 실제로 비추게 두면 감쇠가 생겨 빛으로 읽힌다. 발광은 출처(작은 틈)에만 |
| 케이스가 한 자릿수면 **전수 측정한다** | 밤을 1,2,5,6,8만 재고 "확인했다"고 적었다. 4와 7은 실제로 한 번도 안 쟀다 |
| 수치를 문서에 상수로 쓰기 전에 **두 번 잰다** | 검증 하네스의 대기 시간이 섞여 총합이 4~9초씩 흔들렸다 |
| 일괄 치환은 **미적용 항목을 반드시 보고**하게 만든다 | `String.replace` 미스매치가 조용히 통과해 문서 개정이 누락됐다 |
| ⭐ **판정을 지우면 검증 하네스가 그 판정으로 만들던 상태도 함께 잃는다** — 지우기 전에 "이걸로 무엇을 재고 있었나"를 먼저 센다 | v0.11.50에 놓침 판정을 뺐더니 깊이 사다리(늘어남 3회 → soft fail)를 만들 방법이 사라졌다. 남은 결정적 경로(차도)로 갈아탔다 |
| 기능을 **뺄 때도 실측으로 확인한다** — "안 걸린다"가 아니라 "0이 나왔다" | `흔적 지나침: stretches 0 · depth 0`이 클릭 제거의 유일한 증거다. 코드에서 지운 것과 게임에서 사라진 것은 다른 주장이다 |
| ⭐ **하네스가 가정하고 있던 사람의 행동을 손잡이로 뺀다** | 머무름 임계 4초가 맞는지는 "사람이 몇 초 멈추는가"에 달려 있는데 그건 잴 수 없다. `LOOK_SEC`를 밖으로 빼니 2.5초=자람 0 / 5초=자람 2라는 **비교값**이 나왔다 — 못 재는 값은 고정하지 말고 축으로 만든다 |
| **검증이 도는 중에 `src/`를 고치지 않는다** | vite dev가 리로드를 쏴서 20분짜리 `verify:shots`가 18/21에서 죽었다. 문서(.md)는 모듈 그래프 밖이라 안전하다 |
| 상태 하나를 새로 움직이면 **하네스의 종료 조건을 다시 읽는다** | `verify:play`가 `total` 변화를 "구간 통과"로 읽고 있었다. 머무름 자람이 걷는 도중 total을 올리자 매 구간을 반쯤만 걷고 넘어갈 뻔했다 |
| ⭐ **분위기는 조명이 아니라 재질에서 온다** — 기본색이 한색이면 웜 조명을 아무리 걸어도 진흙빛에서 멈춘다 | 노을을 세 번 틀렸다. 해를 낮춰도, 앰비언트를 올려도 안 됐고 **재질 색상을 돌리자** 됐다. 그리고 밝기까지 같이 올렸다가 화면이 겨자색으로 뭉갰다 — **따뜻함은 색상, 구조는 밝기** |
| 검증 케이스는 **골라 돌릴 수 있어야 한다** | 색 하나 고치고 20분을 기다리면 확인이 작업보다 오래 걸리고, 그동안 소스를 못 고친다. 필터를 넣자 1분 40초가 됐다 |
| 필터·선택 실행은 **안 맞는 인자를 실패로** 친다 | `-- theme-seg1`이 조용히 무시됐다. 0건 실행이 `done`으로 끝나는 것이 가장 나쁘다 |

### 구현 함정

| 관찰 | 왜 |
|---|---|
| `.overlay.hidden`은 자식까지 `pointer-events`를 끊고, 숨길 때 **`blur()`로 포커스도 놓는다** | 숨긴 버튼이 클릭을 가로채고, 포커스를 쥔 채 Space가 구간을 리셋했다 |
| 하단 고정 UI는 서로 겹친다 — 신규 HUD 요소는 상단 우선, **동시 표시 상태를 한 장에** 찍는다 | 조작 힌트가 걷기 버튼·자막과 겹쳤다 |
| 전역 밝기의 레버는 조명이 아니라 **`toneMappingExposure` 배율** | 저장값에 곱연산하면 세이브 마이그레이션이 필요 없다 |
| 스크립트 안의 Windows 경로는 **슬래시**로 (`C:/…`) | 히어독에서 `\\`가 벗겨져 실행이 깨진다 |
| ⚠ **백슬래시가 든 일회용 스크립트는 히어독이 아니라 파일로 쓴다** | 위와 같은 벗겨짐이 정규식(`\\b`)에서도 일어난다. 그런데 이쪽은 깨지지 않고 **아무것도 못 찾은 결과가 나온다** — "죽은 코드 124개"라는 오답을 그대로 믿을 뻔했다 |
| ⭐ **되돌린 시도는 코드를 지워도 주석이 남아 거짓말을 한다** — 되돌릴 때 주석·죽은 헬퍼까지 같은 커밋에서 되돌린다 | v0.11.57에 손자국 분할을 되돌렸는데, 분할용 함수와 그 주석이 남아 **실제로 쓰이는 함수를 "퇴역"이라고 가리키고 있었다** |
| 콘텐츠 퇴역은 코드가 아니라 **데이터에서** | effect 유니온·핸들러는 잔존시키고 JSON 풀에서만 뺀다 (Record 완전성 유지) |
| 컨셉 전환의 마무리는 **용어 grep 전수 사냥** — `docs/`뿐 아니라 **`src/` 주석과 화면 문구까지** | 구 용어가 이론 문서 곳곳에 남았다. 이력(CHANGELOG)은 보존하고 **현행 문서만** 교체한다. v0.11.59가 문서 여섯 개를 고친 뒤에도 코드 주석 여섯 곳과 관리자 패널 문구가 없어진 판정을 설명하고 있었다 |
| 사람이 기억해야 하는 복사 단계는 **스크립트에 넣는다** | `build:local`이 `play-local.html` 복사까지 한다 |
| ⭐ **`gain`은 차이를 벌리고 `lift`는 차이를 지운다** — 밝히려면 어느 쪽인지 먼저 정한다 | lift로 올리자 가장 어두운 아스팔트가 상대적으로 가장 많이 밝아져 벽과 붙었다: 밝기는 올랐는데 **구조가 사라졌다** |
| ⭐ **넓은 면은 거의 무채색으로 두고 색은 작은 면(하늘·등·간판)이 낸다** | 세피아를 고치자 모노핑크가 됐다 — 색상만 옮겼을 뿐 넓은 면을 한 색으로 덮는 것은 그대로였다. **둘은 같은 병이다** |
| ⭐ 하늘·빛무리는 **화면에 실제로 들어오는 띠**에 맞춘다 | 골목에서 보이는 하늘은 지평선 바로 위 좁은 띠뿐인데, 옅어지는 구간과 해의 빛무리(UV의 24%)가 그 띠를 다 덮어 두 하늘 모두 **흰 종이**였다. 물리적 사실보다 보이는 것이 먼저다 |
| ⭐ **`bias`/`normalBias`는 그림자 해상도와 한 몸이다** — 값을 만지기 전에 프러스텀을 줄인다 | normalBias로 acne를 잡으면 벽 밑에 빛이 새고(peter-panning), 빼면 acne가 돈다. 프러스텀을 ±42 → ±28로 좁혀 texel을 4.1 → 2.7cm로 만들자 **normalBias가 필요 없어졌다** |
| ⚠ 방향광의 **target을 옮길 때는 position도 같은 만큼** 옮긴다 | 방향은 `position − target`이다. 한쪽만 만지면 시간대마다 실측으로 잡은 각도가 전부 무너진다 |
| ⭐ **그림자를 켜는 것은 앰비언트를 올리는 일과 한 몸이다** | 그늘에는 앰비언트만 남는다. 그림자 없던 시절의 1.15를 그대로 두니 골목 절반이 밤처럼 새까맸다 — 맑은 날의 그늘은 하늘 전체가 광원이라 **환하고 색만 차갑다** |
| ⚠⚠ **구간마다 부르는 함수가 매 프레임 값을 초기화하는지 본다** | 구간별 `setMorning`을 넣자 그것이 `fog.density`를 시간대 값으로 되돌려, 전환 프레임의 암흑이 지워졌다. 어둠 곡선을 두 번 조정한 것이 안 통한 이유가 이것이다 — **곡선이 아니라 값이 덮어써지고 있었다** |
| ⚠⚠ **이른 `return`은 함수 말미의 동기화를 건너뛴다** — 전환·리셋 경로는 "말미에 뭐가 있나"를 확인한다 | 구간 전환이 `updateWalk` 중간에서 `return`해 말미의 `camera.position.set(…)`에 도달하지 못했다. 그 프레임은 **새 맵을 옛 시점으로** 그렸다 |
| ⭐ 상태를 옮기는 순서는 **가려진 다음에 바꾼다** | 순간이동 → 카메라·어둠 동기 → 세계 교체. 반대로 하면 세계가 바뀌는 프레임이 옛 시점·옛 어둠으로 남는다 |
| ⭐ 화면 결함 제보는 **관리자 모드 좌표**로 받는다 | `Ctrl+Space Space` → C. 이번 세션에서 벽 밑 빛샘·현수막 벽 침범·나무 위치가 전부 좌표 한 줄로 즉시 특정됐다 — 위치를 찾는 왕복이 아예 없다 |
