# 개발 워크플로

이 프로젝트의 작업 절차. 1인 개발 규모에 맞게 단순하게 유지한다.

---

## 파이프라인

```
설계 판정 → 구현 → 검증 → 문서 → 커밋 → (릴리즈면) 배포
```

1. **설계 판정** — 새 기능·이상현상·연출은 [design-principles.md](./design-principles.md)를
   먼저 통과시킨다. 충돌하면 **구현 전에 버린다**
2. **구현** — 콘텐츠는 `src/data/` JSON으로, 로직은 시스템으로.
   콘텐츠 추가에 코드 수정이 필요해지면 멈추고 스키마부터 고친다
3. **검증** — 아래 '무엇을 언제 돌리나'. 코드가 바뀌었으면 `npm run build:local`로
   `play-local.html`도 재생성한다
4. **문서** — 코드와 **같은 커밋**에서. 어느 문서인지는 CLAUDE.md의 문서 맵
5. **커밋** — Conventional Commits + 한국어 제목. `Co-Authored-By` 트레일러는 넣지 않는다.
   버전은 package.json이 아니라 **CHANGELOG.md와 커밋 제목**에

### 무엇을 언제 돌리나

| | 언제 | 무엇 |
|---|---|---|
| `npm run build` | 커밋 전 항상 | 타입 검사 포함 |
| `npm run verify:sim` | 커밋 전 항상 | 깊이 모델 10건, <1초 |
| `npm run verify:balance` | 판정·속도·공간을 건드렸으면 | E2E 6케이스 |
| `npm run verify:shots` | 시각 변경이 있으면 | 이상현상 쌍 + 테마 + 접힘 |
| `npm run verify:play` | 흐름·전환을 건드렸으면 | 첫 방문 → 튜토리얼 → 밤 1 → 집 → 밤 2 |
| `__fries.occlusion()` | 프롭을 더했으면 | 이상현상이 가려지지 않는지 |
| **직접 걷기** | 구간이 바뀌면 | 자동 검증은 "재밌는가"를 답하지 못한다 |

## 콘텐츠 추가

**먼저 [stages.md](./stages.md) §1에서 공통인지 밤(=스테이지)별인지 정한다.**
밤별이면 반드시 데이터로 표현할 수 있어야 한다 — 밤 추가에 코드 수정이 필요하면 설계 실패.

이상현상은 [anomalies.md](./anomalies.md) '추가하는 법' 3단계를 따르고,
끝나면 **stages.md §2 현황판**을 갱신한다.

## 플레이테스트

- 밤 하나가 완성될 때마다 **직접 처음부터** 플레이 (개발자 시점 스킵 금지)
- 외부 테스터에게는 조작법만 알려주고 **규칙은 알려주지 않는다** —
  무설명 학습이 되는지가 이 장르의 핵심 품질이다
- 기록할 것: 오판 지점 · 리셋 후 이탈 여부 · 이상현상별 발견 시간 · 웃은 지점

---

## 릴리즈

1. CHANGELOG에 `vX.Y.Z` 절을 쓰고, 현행 문서(spec·stages·anomalies)를 실빌드와 대조한다
2. `git tag -a vX.Y.Z` — 태그 메시지에 릴리즈 노트를 담는다
3. `git push origin main` — **pre-push 훅이 빌드 + gh-pages 발행을 자동 실행한다**
4. 태그를 올린다: `SKIP_DEPLOY=1 git push origin vX.Y.Z` (main은 이미 배포됐다)
5. **라이브 URL의 에셋 해시가 방금 빌드와 같은지 확인한다** (Pages 반영에 1분 남짓)
6. 모바일 실기기 1회 확인

## 협업 방식 (확인된 선호)

- **확인 질문 대신 결정 후 보고.** 선택지를 늘어놓지 말고 판단해서 진행하고,
  근거와 대가를 함께 말한다. 먼저 물을 것은 **되돌리기 어려운 것**뿐 (배포·삭제·이름 변경)
- **작은 왕복.** 큰 배치보다 한 번에 하나씩 보고 고치는 리듬
- **근거는 실측으로.** "될 것 같다"가 아니라 "이 값이 나왔다" — 스크린샷·수치·좌표를 함께 낸다.
  임계값(응시 각도·신호 주기·이동 속도)은 **가정으로 적지 않는다**

## 이 프로젝트에서 반복적으로 효과가 있었던 것

- **공간 정합성은 눈이 제일 빠르다.** 실플레이 지적이 전부 실제 결함이었다 —
  뒤돌아보니 있으면 안 되는 건물 / 차가 다음 구간까지 따라옴 / 신호등이 둘 다 같은 쪽을 봄 /
  되돌아가면 암흑 막다른 끝.
  → **신규 공간 요소는 "뒤돌아보기 · 구간 넘기기 · 되돌아가기" 세 동작을 반드시 통과시킨다.**
  자동 검증으로는 잘 안 걸린다
- **막고 싶으면 벽보다 연출을 먼저 찾는다.** 되돌아가기 → 골목이 돌려세운다,
  순간이동 → 다리 밑 터널. **보이지 않는 벽은 최후수단**
- **자막은 2줄 이내.** 길게 설명하면 사고가 되고 짧게 흐리면 꿈이 된다.
  정보를 늘리는 대신 **위치를 나눠** 걸음이 문장을 끌게 한다

## 조심할 것

- ⚠ **컨셉을 바꾸기 전에 묻는다 — "이 변경이 플레이어의 동사를 바꾸는가?"**
  하루에 세계관을 다섯 번 바꿔도 상호작용(걷기 + 클릭)이 그대로면 재미도 그대로다.
  픽션 교체보다 **동사를 바꾸는 변경**(신호등·차처럼 기다림에 값을 매기는 것)이 우선순위가 높다
- ⚠ **사람이 직접 하는 플레이가 계속 뒤로 밀린다.** `verify:play`가 끝에서 끝까지
  "동작하는가"는 답하게 됐지만, **"재밌는가"는 여전히 아무도 확인하지 않았다.**
  무설명 학습이 되는지, 어디서 웃는지, 어디서 그만두고 싶은지는 거기서만 나온다

## 배운 것 (실수 → 규칙)

실수를 겪으면 여기에 **규칙으로** 승격한다. "무엇을"이 아니라 **"어떻게"** —
사건의 상세는 CHANGELOG에 있다.

### 설계·배치

| 규칙 | 왜 |
|---|---|
| 이상현상은 **배치 3원칙**(광원 안쪽 · 판정 10m 앞 · 실루엣 대비)을 통과해야 한다 | 입간판이 사실상 안 보였다 |
| 눈높이(1.2m+) 구조물은 **벽면과 평행**, 통행 한계(x±2.6) 침범 금지 | 통로에 수직으로 선 슬랩이 막힌 벽처럼 보이고 카메라가 관통했다 |
| 프롭은 **구간 전체 길이**를 채웠는지 본다 | 사람은 눈에 띄는 앞쪽부터 배치하게 되고, 스크린샷을 '중반'에서만 찍으면 뒷부분은 영영 안 걸린다 |
| **위치로 도는 연출은 "그 위치에 그것이 실제로 있는가"를 조건에 넣는다** | 좌표 조건(`z < -L`)은 지형이 바뀌어도 참이라, 숨긴 지형의 연출만 남는다 (도착지 코앞이 새까매졌다) |
| **결정은 전제와 함께 기록하고, 전제가 사라지면 다시 연다** | "지금은 X가 없으니 Y로 한다"에 X를 명시해야 X가 생겼을 때 검색에 걸린다. 새 장소·새 시스템을 넣는 커밋에서는 "이게 없어서 우회했던 결정"을 훑는다 |
| 무봉합 이음매가 특정 지점의 암흑에 기대고 있다면, 그 지점은 **지나가는 순간에만 존재**해야 한다 | 터널 한가운데를 자유롭게 오갈 수 있어 암흑 막다른 끝이 생겼다 |
| **구간 수명 오브젝트는 전환 시 명시적으로 거둔다** + 매 프레임 가시성 가드 | 한 겹으로는 새어나간다 (차가 다음 테마까지 따라왔다) |
| 시간 제한이 있는 안전 규칙은 **유예 구간이 소요 시간보다 길어야** 공정하다 | 점멸 2.5초 ≥ 횡단 2.1초 |

### 검증

| 규칙 | 왜 |
|---|---|
| 검증 주행의 성공 조건은 "실패하지 않음"이 아니라 **"의도한 만큼 전진함"** | `phase` 변화만 보면 치임·붙잡힘도 통과로 읽힌다. 테마 3·2·1 스크린샷이 한동안 갱신되지 않고 있었다 |
| 커버리지가 줄면 **조용히 줄지 말고 경고**하게 만든다 | 위와 같은 사고를 다음에는 로그가 잡는다 |
| 가시성 판정은 `object.visible`이 아니라 **조상까지** 확인하고, 레이는 그룹 중심이 아니라 **개별 메시**로 쏜다 | 테마 5개가 같은 좌표를 공유한다. 첫 측정값을 믿었으면 멀쩡한 배치를 뜯어고칠 뻔했다 |
| 프롭을 대량 추가하면 **`occlusion()`을 자동으로 돌린다** | 아홉 개 × 여러 각도를 눈으로 보는 것보다 빠르고 확실하다 |
| ⚠ **가림 검사는 '밝기'를 재지 않는다** — 통과해도 **스크린샷을 한 장 본다** | 배치 3원칙은 ①광원 안쪽 ②관찰 시간 ③실루엣 대비 셋인데, 레이캐스트가 답하는 것은 ②뿐이다. 5/5로 통과한 이상현상이 광원에서 9m 밖이라 화면에서는 아무것도 안 보인 적이 있다 |
| 새 물건을 구조물 사이에 끼울 때는 **주변 프롭의 두께와 높이를 먼저 읽는다** | 셔터면(두께 0.12)·보도 단차(y 0~0.14)에 연달아 파묻혔다. 좁은 틈은 이미 꽉 차 있다 — **통행부 바닥은 언제나 비어 있다** |
| 기존 사물을 '바꾸는' 이상현상은 **원래 것을 숨긴다** | 열린 셔터를 닫힌 셔터 위에 겹쳐 두었더니 닫힌 쪽이 그대로 덮었다 |
| 넓은 면에 **발광을 걸면 빛이 아니라 칠한 사각형**이 된다 | 색만 바꾸고 광원이 실제로 비추게 두면 감쇠가 생겨 빛으로 읽힌다. 발광은 출처(작은 틈)에만 |
| 케이스가 한 자릿수면 **전수 측정한다** | 밤을 1,2,5,6,8만 재고 "확인했다"고 적었다. 4와 7은 실제로 한 번도 안 쟀다 |
| 수치를 문서에 상수로 쓰기 전에 **두 번 잰다** | 검증 하네스의 대기 시간이 섞여 총합이 4~9초씩 흔들렸다 |
| 일괄 치환은 **미적용 항목을 반드시 보고**하게 만든다 | `String.replace` 미스매치가 조용히 통과해 문서 개정이 누락됐다 |

### 구현 함정

| 규칙 | 왜 |
|---|---|
| `.overlay.hidden`은 자식까지 `pointer-events`를 끊고, 숨길 때 **`blur()`로 포커스도 놓는다** | 숨긴 버튼이 클릭을 가로채고, 포커스를 쥔 채 Space가 구간을 리셋했다 |
| 하단 고정 UI는 서로 겹친다 — 신규 HUD 요소는 상단 우선, **동시 표시 상태를 한 장에** 찍는다 | 조작 힌트가 걷기 버튼·자막과 겹쳤다 |
| 전역 밝기의 레버는 조명이 아니라 **`toneMappingExposure` 배율** | 저장값에 곱연산하면 세이브 마이그레이션이 필요 없다 |
| 스크립트 안의 Windows 경로는 **슬래시**로 (`C:/…`) | 히어독에서 `\\`가 벗겨져 실행이 깨진다 |
| 콘텐츠 퇴역은 코드가 아니라 **데이터에서** | effect 유니온·핸들러는 잔존시키고 JSON 풀에서만 뺀다 (Record 완전성 유지) |
| 컨셉 전환의 마무리는 **용어 grep 전수 사냥** | 구 용어가 이론 문서 곳곳에 남았다. 이력(CHANGELOG)은 보존하고 **현행 문서만** 교체한다 |
| 사람이 기억해야 하는 복사 단계는 **스크립트에 넣는다** | `build:local`이 `play-local.html` 복사까지 한다 |
